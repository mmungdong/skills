# crwu-audit 总路由（报告审核能力族分发器）

## 0. 目录结构与加载
- `SKILL.md`（本文件，入口 ≤300 行：流程+注册表+指针）
- `references/00-route-profile-schema.md` —— 输入字段与 route_profile 画像 schema
- `references/01-audit-angles-catalog.md` —— 受控审核角度词表（canonical，分发主键）
- `references/02-overlay-rules.md` —— 监管覆盖层判定与冲突检测
- `references/99-维护说明.md` —— **修改本族任何技能/本文档前必须先读**（分层地图/标准流程/红线）
- 本族自含分发逻辑与运行材料，**与知识库仓库解耦**：不预读知识库入口文档、不引用其路径；规则正文与输出/统计/防幻觉契约由部署环境在叶子执行时注入

## 1. 输入（两种来源）
- ① 材料包（目录约定由部署环境注入）
- ② 氚云「报告审核」记录（schema `Srabfcm8figc1xuzxawc5u04x5`，字段清单见 references/00）：
  读取记录全字段 + 附件文件名，按 references/00 产出画像，不依赖人工 manifest。

## 2. 分发算法（每次审核按此执行）
1. **报告形态（第 0 维，先于一切）**：F0000056 → 评估/咨询/估值/矿业权；
   咨询/估值=参照口径（RULE-01-02-435），无"评估结论/有效期"表述；
2. **经济行为主线**：F0000065 × F0000064 → references/01 受控角度词表 canonical；
   业务大类/目的为空（基线约 700 条）→ 读报告名称 F0000049 推理兜底，推不出报
   "画像歧义，需人工确认"，**禁止猜测分发**；
3. **对象大类/范围**：F0000119 × F0000066 → 挂对象专项；
4. **方法**：记录字段无方法 → 附件文件名提示 + 抽验报告/评估说明方法章节回填
   `methods[].confirmed`（来源=附件名/待抽验/材料确认）；
5. **监管覆盖层**：按 references/02 四类判定（国资/证券/司法/金融）装载覆盖层规则集；
6. **分层路由**：L1 大方向匹配（§3 注册表）→ L2 细分匹配 → 未命中细分降级父大方向 →
   大方向未命中用跨对象通用评估报告规则动态装配 → 仍无依据如实返回"暂无对应审核能力/无 A 级依据"；
7. **冲突检测**：字段画像 vs 材料/报告自述不一致 → ROUTE001–004（references/02）；
8. **门禁透传**：命中技能依赖规则 A 待发布 → 全程试点模式（意见标 `[依据待发布]`）；
9. **汇总输出**：意见按 报告/评估说明/测算明细表 分区去重；附路由路径、适用规则集快照、
   route_profile 摘要与三段式引用（KB 06/07，禁止放宽）；
10. **统计回填**：route 命中/降级/空能力/weak_structured 计数 → KB 08 台账。

## 5. 边界与纪律
- crwu-audit 只编排：不产出具体审核判断、不替叶子技能下结论；
- 材料缺件/画像歧义 → 先报告缺什么/列出可能画像请用户确认，不猜测；
- 风险等级 ABC、报告审核级次、状态 **不参与路由与判定**（同业务角度同审核逻辑）；
- 维护/变更必须按 references/99 流程执行（含两处拷贝同步 + design/README/CHANGELOG 登记）。
