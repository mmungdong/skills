# crwu-dws references/02 —— 目录缓存与兜底查找规范（缓存层 / node-index / M3 协议）

> 版本 v1.2（2026-09-08：v1.1 随 crwu-dws v0.3.1 新增 §2 缓存身份与名一致性清理层，原 §2–6 顺移为 §3–7；v1.2 随 v0.4 新增 node-index 全路径键 `by_path`（M3 路径寻址）与路径命中报告口径）。
> 本文档随技能安装（源仓与运行时双份）；
> 改前先读 `docs/design-crwu-dws.md` §6 缓存与实时性模型、§10 D8–D12。

## 1. 核心原则（用户口径，不可违反）

1. **目录可缓存**：目录结构与 nodeId 映射变化低频 → 本地缓存。
2. **正文不缓存**：正文内容永远现场从钉钉导出（下载时点=钉钉当前版）；M2 下载物仅供本次审核，跨审核必须重新下载。
3. **缓存不是事实源**：事实源 = 钉钉实时。缓存只用于"少跑在线遍历"；任何"存在性"权威结论须来自一次成功刷新或如实降级。
4. **未命中必刷新**：缓存查不到 → 自动在线刷新 → 重查；仍无 → 如实报告"没找到"，不编造。
5. **防幻觉**：报告必须带结论依据标签（§6）；刷新失败不得用旧缓存冒充新鲜。
6. **缓存名一致（v0.3.1）**：缓存目录只对与其身份一致的目标库有效；身份（§2）与 skill 目标库名不一致 → **先清理该缓存目录、在线重下后再用**，禁止把别的库的缓存当目标库索引（跨库误命中；SKILL.md §5.0）。

## 2. 缓存身份与名一致性清理（缓存库名 ≠ 目标库名 → 清理重下）

1. **身份**：每个缓存目录的身份 = `.cache-meta.json.space`：`{name, workspaceId}`（服务端真实返回；两字段齐备才可证实身份）。
2. **一致性基准（目标库名）**：skill 默认目标名「中瑞世联评估审核知识库」或本次指定库名。M1 与 M3 刷新路径叠加 P1 解析结果，按 name+workspaceId 双匹配对账；M3 命中路径不发起在线遍历，以请求库名做名级对账（workspaceId 一致性在写缓存时已由 P1 校验并固化于 meta）。
3. **判据与动作**：身份与目标不一致（名级或双匹配）→ **整体删除该缓存目录**（正式 4 文件 + 残留 `.tmp-*`），再**在线重下目标库目录结构**（= 一次成功完整遍历 → §4 写缓存原子替换 → 重查）。meta 缺失/损坏 → 身份不可证实：目录名 ≠ 目标库名 → 同前删除重建；目录名 == 目标库名 → 不删除，按 §7 缓存损坏走刷新覆盖重建。
4. **范围与安全**：删除只作用于 `dws-dir-cache`——目录缓存 = 可再生中间产物、无正文，删除即清理协议、不违红线；不碰 M2 当前审核 `knowledge/` 工作集或远端。删除失败 → 该缓存按不可用处理并报告路径问题，不静默复用。
5. **防跨库误命中**：node-index 查找只允许发生在与本次目标一致的缓存目录内；被清理目录禁止在清理前被查询。
6. **清理报告**：删除动作与原因必须可见（"已清理不一致缓存：<目录>（缓存 space=<…>，目标=<…>）"）。

## 3. 缓存布局与文件格式

```
~/.crwu/knowledge/dws-dir-cache/<库名>/            # 多库各一份；同名多空间 → 追加 -<spaceType>（身份见 §2）
├── 目录快照.json       # crwu.kb-catalog.snapshot.v1（references/00）——目录元数据唯一事实文件
├── 目录树.md           # 人读视图（快照渲染，不单独成为事实）
├── node-index.json     # 查找索引（可由快照重建；写缓存时同步重建）
└── .cache-meta.json    # 缓存元数据（fetched_at/evidence/统计）
```

- 缓存目录内**禁止出现任何正文内容文件**（md 正文副本、导出文件等）；`.tmp-*` 只允许出现于原子替换的瞬时窗口，替换完即无。
- 父目录 `~/.crwu/knowledge/` 不可写 → 报告路径问题，不静默改落点、不把正文改存他处绕过红线。

### node-index.json（`crwu.kb-dir-cache.nodeindex.v1`）

```jsonc
{
  "schema": "crwu.kb-dir-cache.nodeindex.v1",
  "space": { "name": "…", "workspaceId": "…", "spaceType": "…" },
  "built_from_snapshot_at": "ISO8601",
  "by_node_id": { "<nodeId>": { "name": "…", "type": "…", "folderPath": "顶层folder/子folder…或空", "depth": 1, "parentNodeIds": ["…"] } },
  "by_name": { "<精确名称>": ["<nodeId>", "…"] },  // 同名多命中 → 数组多条
  "by_path": { "<目录链>/<名称>": ["<nodeId>"], "<目录链>/<文件夹>/": ["<nodeId>"] }  // 全路径键（v0.4，路径寻址）；folder 键尾带 "/"
}
```

- `folderPath` = 从根到父的 folder 名称链（不含 node 自身），用于报告树路径上下文；由快照推导，快照缺字段则留空并在索引条目注 `path_partial:true`。
- 名称索引 key 使用**原样精确名**（不折叠大小写/空白/全半角）；查找时同样精确比对——歧义宁可多命中消歧，不做模糊近似命中。
- `by_path` 全路径键 = 从根起的完整层级链（`folder/…/名称`；folder 节点键尾加 `/`）：供 M3 文件级精确命中 / 目录前缀展开（键前缀匹配）；同层同名等罕见冲突 → 值可为 nodeId 数组并在报告全列消歧；由快照重建，写缓存时与 `by_name` 同步生成。

### .cache-meta.json（`crwu.kb-dir-cache.meta.v1`）

```jsonc
{ "schema": "crwu.kb-dir-cache.meta.v1",
  "space": { "name": "…", "workspaceId": "…", "spaceType": "…" },
  "source": "dingtalk-live",
  "last_successful_at": "ISO8601",      // 最近一次成功完整遍历并写缓存时刻
  "last_refresh_attempt_at": "ISO8601",
  "last_failure": null,                 // {at, error} 或 null
  "stats": { "total_nodes": 0, "complete": true },
  "profile": { "id": "…", "isOrgCurrent": true } }
```

## 4. 写缓存（原子替换；M1 与 M3 刷新共用）

1. 遍历完成且 P4 计数一致（`failures=[]`、每页 `autoPageComplete=true`）才进入写缓存；
2. 依次写 `.tmp-目录快照.json` / `.tmp-目录树.md` / `.tmp-node-index.json` / `.tmp-.cache-meta.json` → 全部成功后再逐个 rename 覆盖正式文件（顺序：meta 最后覆盖，保证 meta 落成即代表整套新缓存可见）；
3. rename 失败 → 保留旧缓存，`last_failure` 记录，摘要说明"缓存未更新：<原因>"；
4. `complete=false`（遍历不完整）→ **不写缓存**（保留旧缓存），并在报告标注。

## 5. 正文实时拉取协议（M3 命中取正文 / 任何"要最新内容"场景）

1. 目标 = 已知 nodeId（来自缓存命中或刷新后命中）；拉取 = `dws doc +export --node <nodeId> --export-format markdown`；
2. 导出位置 = **本次审核工作目录或系统临时目录**（不属于缓存层）；回执 `localPath`+`sizeBytes>0` 即终态；
3. 交付内容仅供本次审核推理；进入案例 `knowledge/` 时按 M2 单文件语义登记 manifest，进入临时目录时使用完即清理；两者都**不进缓存层且不得跨审核复用**；
4. 拉取失败 → 如实报告（失败原因 + 不提供任何"缓存正文"替代——因为缓存根本没有正文）。

## 6. M3 报告口径（结论依据标签必含其一）

| 情形 | 报告模板 |
| --- | --- |
| 缓存命中 | `缓存命中（fetched_at=<…>）：<名称>（<type>），目录 <folderPath>，workspaceId=<…>（<spaceType>）`；要正文 → 转 §5 |
| 名称/路径多命中 | `同名/同路径 <n> 个（缓存 fetched_at=<…>）：逐一列 <folderPath>；请指定 nodeId`（不猜） |
| 路径命中（文件级） | `路径命中（fetched_at=<…>）：<名称>（<type>），目录 <folderPath>，workspaceId=<…>（<spaceType>）`；要正文 → 转 §5 |
| 目录前缀命中 | `目录前缀命中（fetched_at=<…>）：<目录> 下条目 <n> 个（folder/adoc/axls/… 分类列出）` |
| 刷新后命中 | `刷新后命中（刷新于 <时间>）：…` |
| 刷新后仍无 | `未找到：<名称/nodeId/路径>（目录已刷新至 <时间> 后仍不存在）；相近候选：<名称列表 ≤5>` |
| 降级（刷新失败有旧缓存） | `缓存可能过期（fetched_at=<…>，刷新失败：<原因>）：<按旧缓存作答>，结论不具权威性` |
| 无法确认 | `无法确认（缓存缺失且在线刷新失败：<原因>）` |
| 未找到且无候选 | `未找到：<名称/nodeId/路径>（目录已刷新至 <时间>，无相近候选）` |

- "相近候选"来自刷新后快照的简单名称包含匹配（≤5），仅作提示，**不视为命中**。

## 7. 校验与自查

- 缓存完整性：`.cache-meta.json` 的 `last_successful_at` 与 `目录快照.json.generated_at` 一致；`node-index.json.built_from_snapshot_at` 一致；任一文件 JSON 解析失败/缺失 → 视为缓存缺失，M3 自动刷新重建。
- 缓存身份自检：缓存目录名与其 `.cache-meta.json.space` 指向一致；身份与目标库名不一致的目录按 §2 清理重建（SKILL.md §5.0）。
- 正文红线自查：缓存目录递归列出，只允许 4 个正式文件 + 瞬时 `.tmp-*`；出现其他文件 → 报"缓存目录被污染"并报告（不自动删除用户文件，提示人工处置）。
