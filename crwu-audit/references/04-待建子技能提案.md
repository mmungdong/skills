# references/04 · 待建子技能提案（路由兜底 → 自动推导"补哪个子技能、管什么、审什么"）

| 版本 | v0.1 | 状态 | 定稿（2026-09-07） | 维护 | crwu-audit（改前先读 99） |
| --- | --- | --- | --- | --- |

> 用途：当"评估目的 × 评估方法 × 评估对象"路由后**没有可用子技能**（已登记未实现 🅿️/⏳，或注册表
> 无该组合）时，按本文五查推导并输出《待建子技能提案》卡，随路由级兜底报告交用户——让用户一眼看到
> "该补哪个子技能、它主要负责什么、需要审核什么、依据哪些现成规则、还缺什么材料"。
> **提案=建议与证据，不是审核结论，不修改任何文件**；落地执行统一走 `crwu-audit-optimize`
> （先《优化方案》→用户确认→99 流程→kb_tool 校验回归）。

## 1. 触发条件（满足其一）

1. L1/L2 全未命中，进入路由级兜底（含弱结构化名称兜底后仍无技能）；
2. 命中的技能在注册表为 🅿️（已登记待建）/ ⏳（待定）；
3. 注册表无 (报告形态 × 评估目的/业务主线 × 对象 × 方法 × 场景) 组合，且词表/目录地图/数据基线
   佐证该组合应有审核能力（对象有体量或对象目录已规划）。

> 画像歧义（业务大类/对象推不出，须人工确认）**不产提案**，只输出"画像歧义"提示——猜画像的提案
> 会污染待建清单。

## 2. 输入（证据源，缺一不可）

- route_profile 画像五维（形态/对象/目的主线/方法/监管覆盖）；目的与方法须有出处
  （字段直读或文件抽验），未抽验的标"待抽验"；
- 路由注册表快照（crwu-audit SKILL §3，含 🅿️/⏳ 状态）；
- KB 现状证据（机器查询，命令见 §3）＋ 数据基线 count（`00-总纲/目录地图.md` 行）。

## 3. 推导步骤（五查）

1. **查技能**：注册表有没有同名/近义登记项？
   - 有（🅿️/⏳）→ 提案=「细化已登记技能」：职责、审核范围、前置条件；
   - 无 → 按命名规范提出候选名（L1：`crwu-audit-<对象大类>`；L2：`crwu-audit-<父级>-<细分>`，英文小写连字符）。
2. **查词表**：画像用到的 object_type / method / scenario 取值是否已登记
   （经 crwu-dws 实时下载 `00-总纲/治理/标签词典.md` 后查）？未登记 → 提案"前置登记项"（新技能启用前先登记取值）。
3. **查依据**：库内现成可引用的 RULE/CHK 段（机器查，命令模板见下）：
   ```bash
   kb_tool.py assemble --profile <画像.json> --out 装配清单.md   # 命中/排除（含原因）
   kb_tool.py query --module M-市场法
   ```
   （kb_tool 机器查询 = 维护/现状登记用途的可选增强，不影响 crwu-dws 实时下载正文主路径；
   正文引用一律以实时下载为准，下载不可得 → 如实报告，禁止读本地静态副本冒充实时。）
   对象层无精编但通用/方法层有 → 提案注明"先按通用+方法层规则覆盖执行，对象细则待补精编"。
4. **查目录**：经 crwu-dws 查知识库目录 `02-资产类型/`（层级路径）下对应对象目录 与 `01-业务路线/`
   下对应路线目录 的内容状态
   （精编目录=内容就绪 / 索引卡 / 仅 README=内容缺口），区分"只缺技能"还是"技能+内容都缺"。
5. **查体量**：目录地图对应行 count → 建议优先级（count 降序：P0/P1/P2）。

## 4. 输出：《待建子技能提案》卡（schema）

| 字段 | 说明 |
| --- | --- |
| 提案编号 / 日期 / 来源单子 | 便于用户引用与 optimize 跟进 |
| 候选技能名 | 注册表已登记则沿用其名并标"细化" |
| 触发画像 | 形态 × 目的主线 × 对象 × 方法 × 场景 组合行（原文出处） |
| 定位与职责 | L1 大方向 or L2 细分（挂哪个父级）；负责哪些公共逻辑/叠加能力（表格勾稽→datacheck、披露/基准要素→对应 M-模块装载） |
| 需要审核什么 | 分区（报告/评估说明/测算明细表）与优先检查点：可复用现成 CHK ＋ 需新建清单项的建议起点（每条给依据段） |
| 依据段（现成） | 可引用的 RULE id 清单 ＋ 文件:行号 |
| 内容缺口（待补） | 需补精编的官方原文/指南清单；或仅需技能不需补内容 |
| 前置登记项 | 词表取值登记、三处登记（路由注册表 + design §4 + skills/README）、新 SKILL 自带"仅经 crwu-audit 编排调用"门禁、部署联动登记（运行时由用户 skills 管理机制部署，本侧不直接写运行时） |
| 建议优先级与引用口径 | count 依据；无发布门禁（口径 2026-09-08：知识库文档即权威、下载即审，无发布/试点状态判定与标注） |
| 证据附件 | 命令与输出（assemble/query），保证可复现 |

> 生成纪律：一个画像组合最多一张卡；先匹配注册表已登记项再提新名；只产"库内确实无能力"的卡；
> 通用兜底已够用且对象无体量 → 不产卡并注明原因（"体量小走参照口径"）。

## 5. 示例卡（真实现状：机器设备 × 转让/处置）

```markdown
# 《待建子技能提案》P-2026-09-001（机器设备·转让处置）
- 触发画像：评估报告 × 转让处置-资产 × 设备类（单项资产） × 成本法/市场法 × 国资（常见）
- 注册表现状：`crwu-audit-equipment` 已登记 🅿️（P1）→ 本卡=「细化已登记技能」
- 定位与职责：L1 大方向技能。对象层（设备特性：成新率/贬值/拆卸安装费等细则规则）+ 通用披露
  （报告准则 RULE-01-02-251~279）+ 方法适用（成本法/市场法，RULE-01-02-281~305 段）
  + 叠加能力：材料含明细表 → datacheck（C1–C6）；国资场景 → 04-监管覆盖/国资 装载。
- 需要审核什么：按 报告/评估说明/测算明细表 分区。起点检查点：
  ① 设备清单与汇总勾稽（复用 M-数据校对口径 + datacheck 差异清单回判）
  ② 成新率/贬值/修复费用取值与底稿一致（需新建 CHK-EQP 系列，建议挂 M-成本法）
  ③ 权属与转让披露（复用 M-报告披露 项）；④ 方法选择披露（RULE-01-02-301~304）
- 依据段（现成）：RULE-01-02-281~305（方法）＋ RULE-01-02-251~279（报告）
  ＋ M-数据对齐 模块 RULE（勾稽口径）
- 内容缺口（待补）：02-资产类型/机器设备 现仅 README——设备评估规则官方原文→精编（对象层 RULE 段）
  ＋ 设备型清单 CHK-EQP 编撰；词表「单项资产评估」已登记待启动（可直接启用）
- 数据依据：目录地图 转让/处置 936 + 了解价值 287 → P1（在 P0 房地产之后）
- 前置登记：词表启用「单项资产评估」→ 三处登记 → 新 SKILL 门禁文案 → 部署联动登记（运行时由用户管理机制部署）
- 证据附件：kb_tool query 输出（2026-09-07，见随附）
- 边界：非审核结论；落地走 crwu-audit-optimize（先方案后执行）
```

## 6. 边界与衔接

- 提案随兜底报告输出，标注"依赖子技能暂未实现/未登记——非审核结论，待用户补充或走 optimize 正式化"；
- 用户对卡做补充/批注后 → `crwu-audit-optimize`：以提案卡为 B 桶输入，细化成《优化方案》文件清单
  （新 SKILL.md 骨架、词表登记行、三处登记、校验回归），确认后执行；
- 注册表/词表/目录地图变更时本文件规则不用改，但旧提案卡随之作废——重新触发路由再生成；
- 禁止：凭提案卡直接产出规则性审核意见；把"待建"当"已建"继续分发（未登记前仍走兜底）。
