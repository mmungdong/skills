> 本文件把"审核能力族 + 知识库"的维护规范固化成**改动类型→唯一落点**地图：优化动作只许动对应落点，

## 1. 引用协议与运行时真身（2026-09-08 实时引用协议同步，见 design-audit-live-kb-protocol §2 R1–R5）

- **知识库 = 钉钉知识库（crwu-dws 实时下载源）**。技能正文不保存、不缓存知识库正文：引用一律写
  RULE/CHK 编号 + 库内层级路径寻址键（如 `00-总纲/目录地图.md`、`06-规则库/…`），不写知识库名称、
  不写本地根路径字面、不写 nodeId；需要正文时经 crwu-dws 按路径实时下载后只读引用
  （出处 = 本次下载文件:行号 + exportedAt，下载时刻即最新）。校验 = `kb_tool.py validate --skill-root …`
  （含"三不写" lint：禁知识库名称 / 禁本地静态根路径字面 / 禁 nodeId 常量；路径存在性校验过渡双轨见 §4）。
- **运行时真身 = `~/.skills-manager/skills/`**；`~/.dsh/skills/` 与 `~/.workbuddy/skills/` 是其软链视图
  （三者指向同一份文件）。维护 = 源仓 ↔ 运行时真身 双份同步：两处 `diff -r` 为空即三处视图一致
  （软链视图随真身自动一致）。
- **工具**：`kb_tool.py`（源仓 `tools/kb/`；子命令 index/validate/resolve/query/release/assemble/extract/selftest；
  可执行路径由部署环境注入；无工具时按装配表定位引用路径，正文一律经 crwu-dws 实时下载后人工核对，
  但**方案必须附手工证据**；下载不可得 → 显式报告，禁止读本地静态副本冒充实时）。
- 本技能 references 随技能安装，内容自带寻址键表与落点地图，不回指 skills/README（该文件不装到 agent）。

## 2. 分层地图（改动类型 → 唯一落点）

> 文内『KB/知识库』= 钉钉知识库（crwu-dws 实时下载源）：规则/清单/契约/门禁等正文只在其内，技能不复制正文；
> 下表 `00-总纲/…`、`06-规则库/…` 等均为库内层级路径（寻址键），正文需要时经 crwu-dws 实时下载后只读引用。

| 改动类型 | 唯一落点 | 联动 / 红线 |
| --- | --- | --- |
| 规则/清单正文（RULE/CHK 依据、判定要点、检查点、新增条目） | KB `06-规则库/`（精编条目 / `M-*` 模块 / `清单-M-*`）＋对应批次 README | 词表先登记；`### <id>` 定义锚点唯一；A 级发布=质控人工；B/C 禁作硬依据 |

| 路由/分发/降级/覆盖层/业务分类判定 | crwu-audit `SKILL.md`（§2 分发、§3 注册表）＋ `references/02`/`03` | 与 design §4 能力树同步；示例路由同步 |
| 叶子审核逻辑/算法/流程（分区、C1–C6、去重、输出流程） | 对应叶子 `SKILL.md`（realestate / realestate-rent / datacheck …） | 公共逻辑只在大方向技能一份；细分只写增量，禁止复制正文 |

## 2.1 知识库变更的同步义务（索引 / 装配表 / 目录地图 三件套）

> **铁律：知识库有任何内容或结构变更，`kb-index.jsonl` 必须与变更同批重跑刷新**（其 `_meta.files`
> 存每文件 hash，过期即 `validate` 报 error）。装配表/目录地图只在"路径/指针/装配范围"受影响时改，
> 但**禁止出现"知识库已改、索引没刷"或"文件已动、指针没跟"的中间态**——本流程收尾以
> `validate` error=0 ＋ 受影响装配两跑一致 为准。

| KB 变更类型 | 必做同步 | 说明 |
| --- | --- | --- |
| 条目正文/判定要点/dims/modules/标题（同文件内编辑） | ① `kb_tool.py index` 重跑 ② validate ③受影响装配两跑 | 装配表指针不受影响，不用动 |
| 同文件新增条目 | ① index 重跑 ② 批次 README/进度总表对应行（条目计数/段位变化时） | 新增条目须先登记词表取值（若用新标签）；`### <id>` 锚点唯一 |
| 新增/改名/移动/删除 KB 文件或目录 | ① 受影响叶子的 `references/00-KB装配表.md`（逻辑指针行）② KB `00-总纲/目录地图.md`（画像→目录行）③ 相关文档内引用文本 ④ index 重跑 ⑤ validate | 改名前先 grep 全库引用（装配表/SKILL/治理文档），一个不漏 |
| 装配范围/模块标签体系变化（某技能该装哪些清单与规则段） | ① 对应叶子 `references/00-KB装配表.md` ② 词表登记（若模块/取值变化）③ index 重跑 ④ validate | 影响"命中/排除"语义，须重跑受影响画像两遍验证 |
| 发布状态翻转（A 待发布→已发布，回填 curated_by/reviewed_on） | ① index 重跑（release 列才更新）② 待发布清单同步 | **翻转动作=质控负责人人工执行**，本流程只读、只提醒"发布后必须重跑 index" |
| KB 引用路径/文件名出现在技能正文中（SKILL.md） | ① 技能正文同步 ② 装配表同步 ③ validate --skill-root | 个人绝对路径、「KB/…」式前缀省略（技能引用一律=库内层级路径寻址键）、知识库名称 / 本地静态根路径字面 / nodeId 常量禁止（三不写 lint） |
| 校准/回测结论更新（案例覆盖、缺口 G） | ① `校准案例记录.md`/`回测报告-真实案例覆盖.md` 回填 ② 受影响清单/规则条目若改→按首行"index 重跑" | 回测与规则互为证据链，不同步=下次优化失去基线 |

## 3. 红线（不许绕过）

1. **未出方案、未经用户确认，不动任何文件**（含 KB 内容）；
2. 不产审核判断、不出正式/试点审核意见（那是 crwu-audit 流程）；
3. 不翻转发布状态、不回填 curated_by/reviewed_on（质控人工）；
4. 不把规则/清单正文复制进技能（技能=流程+寻址键+算法，正文=钉钉知识库，即 crwu-dws 实时下载源）；
5. 编号唯一性以定义锚点为准（正文区间引用不算重复）；
6. 个人绝对路径、「KB/…」式前缀省略（技能引用一律=库内层级路径寻址键）、旧树目录名（01-规则库/02-审核清单库/执业准则-*/06-素材库-L2 等）一律禁止出现；
7. SKILL.md ≤300 行；改 crwu-audit 族技能前先读 `crwu-audit/references/99-维护说明.md`；
8. 每次改动双份同步：源仓 ↔ 运行时真身（`~/.skills-manager/skills/`；`~/.dsh/skills` 与 `~/.workbuddy/skills` 为其软链视图），`diff -r` 为空即三处视图一致；登记三处（design/README/CHANGELOG）。

## 4. 验收基线（每次优化完成后必须全过）

```bash
# 1) 改了知识库规则文件才需要重建索引
kb_tool.py index
# 2) 双份校验：error 必须为 0（warn 相对基线不得增加）
kb_tool.py validate --skill-root <源仓>/skills --skill-root <运行时真身>/skills
#    validate 含"三不写" lint：禁知识库名称 / 禁本地静态根路径字面 / 禁 nodeId 常量；
#    引用路径存在性校验为过渡双轨（本地静态根 OR crwu-dws 目录快照；无快照过 lint 即过）；
#    推理/回归中的正文引用一律以 crwu-dws 实时下载为准，不读本地静态副本冒充实时。
# 3) 装配可复现：受影响示例（含本单画像）两跑 diff 为空
kb_tool.py assemble --profile <画像>.json --out a.md && kb_tool.py assemble --profile <画像>.json --out b.md && diff a.md b.md
# 4) 试点回归：BG8169 / 300673 输出不劣化（见知识库回测报告 §5）
```

通过判据：error=0；装配两跑一致；受影响试点无劣化；源仓 ↔ 运行时真身 diff 空（三处视图一致）；登记完成。任何一条不过 → 回到方案修订。

## 5. 顺序纪律（确认后的执行顺序）

落点文件 → 引用它的上层文件 → 运行时真身同步（diff 核对，软链视图随动）→ 登记（词表/路由表/design/README/CHANGELOG/批次 README）→
index/validate → 装配两跑 → 试点回归 → 汇报（文件级清单 + 校验结果 + 剩余风险）。
