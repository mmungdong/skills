> 知识库（KB）= 钉钉知识库，即 crwu-dws 实时下载源：本模板的拟改文件清单涉及知识库文件时只写库内层级路径
> （如 `00-总纲/…`），正文一律经 crwu-dws 实时下载后只读引用（出处=本次下载文件:行号+exportedAt），
> 不写知识库名称 / 本地根路径 / nodeId，不做任何正文缓存。

## 1. 方案必答项（逐项齐全才可提交确认）

```markdown
# 《优化方案》<编号/日期/单子或反馈摘要>

## 1. 问题与证据
- 反馈原文（引用用户原话）
- 单子画像：形态 / 对象(02) / 业务主线(01) / 方法(03) / 监管覆盖(04)
- 证据：装配清单 / 规则段落(文件:行号) / 历史审核产物 / 回测编号 / validate 输出（至少其一）

## 2. 分桶结论
- 根因桶：A 规则内容 / B 覆盖缺失 / C 词表画像 / D 技能算法 / E 路径漂移
- 影响面：涉及哪些叶子技能；涉及哪些 KB 目录

## 3. 拟改文件清单（确认后逐文件执行；未确认不动）
| # | 文件（源仓路径） | 部署说明（运行时由用户 skills 管理机制负责；本列不再列运行时路径） | 改动说明（一句话） |
| 1 | skills/crwu-audit-xxx/SKILL.md | —（提交源仓即交付，由管理机制部署） | … |
| 2 | 知识库库内文件：`00-总纲/…`（库内层级路径寻址键；正文修改按知识库内容维护流程另办） | —（知识库正文不复制进技能；引用经 crwu-dws 实时下载） | … |
| 新增文件：目录 + 文件 + 内容概要 + 预计条数/行数

## 4. 联动登记（随改动同步完成）
- [ ] 标签词典（若涉及词表取值）   [ ] 路由注册表（若涉及技能/路由）
- [ ] 叶子 `references/00-KB装配表.md`（新增/改名/移动 KB 文件或装配范围变化时）
- [ ] KB `00-总纲/目录地图.md`（同上，画像→目录行）
- [ ] `kb_tool.py index` 重跑（**凡涉及 KB 内容/结构变更必做**；索引时间须晚于变更）
- [ ] design-crwu-audit-skills.md   [ ] skills/README.md   [ ] docs/CHANGELOG.md
- [ ] 批次 README / 进度总表对应行   [ ] 校准案例/回测记录回填

## 5. 校验与回归步骤（具体命令）
（照抄 references/00 §4，若方案只改技能不碰 KB 规则文件，index 可省略但 validate 必跑）

## 6. 不做项与风险
- 明确写"本次不做"（如：版本管理、钉钉迁移、基线脚本复跑）
- 风险：影响现行审核？需人工复核点？回滚方式（git checkout / 拷贝还原）？
```

## 2. 确认门禁

1. 方案输出后**必须停下等待**；用户说"按方案执行/可以/同意"（含逐条同意）才算确认；
2. 确认粒度：整体或逐条；逐条驳回的条目不得执行，其余条目照常；
3. 驳回 → 记录驳回原因（写入方案"驳回记录"），缩小范围后可重提（引用原编号）；
4. 执行中发现超出方案范围的新问题 → 立即停下，回到 §1 重新出方案，禁止顺手改；
5. 涉及"新增 crwu-audit-* 叶子技能"的方案：三处登记 + 自带"仅经 crwu-audit 编排调用"门禁
   缺一不可（99 流程），并明确"不装到运行时则不影响路由"的预期。

## 3. 执行后核对清单（完成即勾）

- [ ] 落点文件已按 §3 清单改完（无清单外改动）
- [ ] 源仓已提交；运行时部署已交由用户 skills 管理机制执行/校验（本侧未直接写运行时）
- [ ] 登记全部完成（§4 联动清单；涉及 KB 时含装配表/目录地图/index 重跑）
- [ ] `kb_tool.py index` 已重跑且索引时间晚于本次 KB 变更（凡涉及 KB 内容/结构）
- [ ] `kb_tool.py validate` error=0（warn 不劣于基线）
- [ ] 受影响装配示例两跑 `diff` 为空
- [ ] BG8169 / 300673 案例输出不劣化
- [ ] 汇报已发出（文件级改动 / 校验结果 / 剩余风险与待办）
