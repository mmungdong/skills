# 报告标识解析

| 版本 | v1.0 | 状态 | 2026-09-09 定稿 | 维护 | 报告记录唯一定位规则 |
| --- | --- | --- | --- | --- | --- |

1. `ObjectId` 只能来自用户明确输入，或一次真实查询的返回结果。
2. 输入为 `SeqNo` 时，必须对报告审核（report-audit）schema 的 `SeqNo` 字段做精确查询，并解析为唯一 `ObjectId`。schema code 必须来自现场可验证的 schema 查询结果或已确认的配置。
3. 精确查询返回 0 条时立即停止，返回：“未找到该报告流水号”。
4. 返回多条时，列出可供识别的候选记录（至少 `SeqNo`、报告名称、更新时间、`ObjectId` 尾段），然后停止并等待人工确认。
5. 不得猜测 schema code 或 `ObjectId`；不得用模糊报告标题匹配代替精确 `SeqNo` 查询；不得在 0 条或多条时自行选择。
6. router 只获取一次报告记录，以该快照构建 `route_profile`并准备材料路径。leaf skill 只消费 `route_profile` 与已准备好的材料路径，不重复查询报告记录。

字段与报告材料出现标识冲突时，将真实值和来源写入 `conflicts[]`，停止使用受影响的记录身份，等待人工确认。
