# crwu-audit-optimize（审核能力族 · 维护/优化入口）

> 本技能**不是审核叶子**：不产出任何审核意见、不参与 crwu-audit 分发。它是"按真实反馈演进族技能与
> 知识库"的总入口：先诊断定位 → 出方案 → **等用户确认** → 按 99-维护说明流程执行 → 校验回归汇报。
> 正式审核请走 `crwu-audit`；技能安装机制 / KB 版本管理 / 钉钉知识库打通属外部事项，本技能不处理。

## 何时用 / 何时不用

| 用（触发本技能） | 不用 |
| --- | --- |
| 反馈"某检查点/口径错了、漏了、过严、缺依据"，要改审核规则 | 正式报告审核 → `crwu-audit`（含试点） |
| 反馈"缺 XX 文档对 XX 文档 / 某业务·对象·形态组合的审核"（路由兜底/空能力） | 发布动作（置 A/回填 curated_by/reviewed_on）→ 质控负责人 |
| 审核结果与规则对不上，怀疑装配/索引/路径漂移 | 氚云/钉钉操作 → h3yun-*/dingtalk-* 技能 |
| 想新增对象方向、方法场景、文档分区的审核能力 | 技能安装/同步机制 → 三方维护 |

## 0. 铁律（先于一切）

1. **先方案、后动文件**：任何修改前必须输出《优化方案》（模板 references/02）并得到用户明确确认；
   禁止"边查边改"、禁止把方案与执行混在同一轮。
2. 本技能不产审核判断、不翻转发布状态、不复制规则正文进技能（正文只在 KB）。
3. 改动只落在 references/00 §2 分层地图对应的**唯一落点文件**；源仓与运行时两处拷贝同步；
   登记 design/README/CHANGELOG（99 流程）。**涉及知识库的变更必须同批完成"索引/装配表/目录地图"
   三件套同步**（判定见 references/00 §2.1）：`kb_tool.py index` 重跑为必做，装配表与目录地图按
   变更类型判定——禁止留下"KB 已改、索引没刷 / 文件已动、指针没跟"的中间态。
4. KB 根常量 CRWU_KB_ROOT=`~/.crwu/knowledge/knowledge-base`；技能引用一律写该根下完整路径，
   禁止个人绝对路径与 `KB/…` 省略号；本技能 references 内容均自带常量，不回指 skills/README。

## 1. 收集与定位（单子画像 → 规则/业务路线/资产类型）

1. 输入：用户反馈原文 + 单子标识（BG8xxx / LX… / 报告名称 / 文号）或材料目录路径。
2. 画像五维（口径与 crwu-audit `references/00-route-profile-schema.md` 一致）：
   报告形态 → 对象大类（→ `02-资产类型/*`）→ 业务主线（→ `01-业务路线/*`）→ 方法
   （附件名提示 + 待抽验，→ `03-评估方法`）→ 监管覆盖（→ `04-监管覆盖`）。
   提取细则见 references/01 §2。
3. 若存在历史审核产物（审核意见单 json/md、路由路径、适用规则集快照），先读——它就是"现状基线"，
   证明当前命中面与真实审核的差异。
4. 机器定位（kb_tool.py；可执行路径由部署环境注入，源仓=`tools/kb/kb_tool.py`）：
   - `kb_tool.py assemble --profile <画像.json>` → 命中/排除（含原因）/发布门禁；
   - `kb_tool.py query / resolve / extract` → 库内现有 RULE/CHK 段及段落原文；
   - `kb_tool.py validate --skill-root <源仓 skills> --skill-root <运行时 skills>` → 漂移线索。
5. 人工对照：`KB/00-总纲/目录地图.md`（画像→目录）、叶子 `references/00-KB装配表.md`（技能→KB 指针）、
   `KB/00-总纲/治理/回测报告-真实案例覆盖.md` 与 `校准案例记录.md`（案例 A/B 已覆盖点）、
   `crwu-audit/SKILL.md` §3 路由注册表（可用/待建/🅿️）。
6. 输出一行定位小结：画像五维 + 现行路由路径 + 命中 M/排除 N + 疑似缺口 X（供用户先纠偏画像）。

## 2. 诊断分桶（根因 → 文件落点，全表见 references/00 §2）

- **A 规则/清单内容**：依据缺失/口径错误/检查点漏项 → KB `06-规则库/` 精编条目、`M-*`、`清单-M-*`。
- **B 覆盖缺失**：对象/业务路线/文档对/阶段无技能或空能力（"缺 XX 文档对 XX 文档的审核"）→ 新建叶子技能
  （先三处登记）或扩装配范围；模式判定见 references/01 §4（**路由兜底自动附的《待建子技能提案》卡
  =本桶输入起点**，见 §4.1）。
- **C 词表/画像**：新取值未登记（object_type/method/scenario/stage/report_type/角度）→ `标签词典.md` ＋
  crwu-audit `references/00`/`01`，并提示部署方复跑基线脚本。
- **D 技能算法与流程**：分区/勾稽/去重/输出/防幻觉执行问题 → 对应叶子 `SKILL.md`（公共逻辑只在大方向一份）。
- **E 路径/装配/指针漂移**：resolve 不到/validate 报错/旧树残留 → 装配表 + `目录地图.md` + 引用文本。

每桶给出：证据（装配输出/回测/规则段落含 文件:行号）、影响面（哪些技能、试点/正式）、最低改动集。

## 3. 《优化方案》输出（必答项，见 references/02 §1）

至少包含：问题与证据 / 分桶结论 / **拟改文件清单**（源仓路径 + 运行时拷贝路径逐文件列出，每文件一句话
改动说明；新增文件列目录与内容概要）/ 联动登记清单 / 校验与回归步骤（具体命令）/ 不做项与风险。
**输出方案后停下，等用户确认**（"按方案执行"或逐条同意/驳回）——未确认不动任何文件。

## 4. 执行（仅在确认后）

1. 按 references/00 §2 顺序改文件（先落点文件、后引用它的上层文件）；涉及 KB 变更时按 §2.1
   同步义务执行（新增/改名/移动 KB 文件或调整装配范围 → 同步叶子 `references/00-KB装配表.md` 与
   KB `00-总纲/目录地图.md`；任何 KB md 内容变更 → 同批重跑 `kb_tool.py index`）；
2. 同步运行时拷贝（本机 `~/.dsh/skills/` 等部署目录），`diff -r` 为空才算同步；
3. 登记：design §4/§7 + `skills/README.md` + `docs/CHANGELOG.md`（99 流程；改词表另提示复跑画像基线）；
   涉及 KB 规则文件的改动同步更新批次 README/进度总表对应行；
4. 校验回归（**全过才算完成**）：
   - 凡改动过 KB 任何 md（正文编辑/新增/改名/移动）→ 先 `kb_tool.py index`，再 `validate`
     （源仓 skills / 运行时 skills / KB 本体）error=0；索引时间须晚于本次 KB 变更；
   - 受影响装配示例（含本单画像）两跑 `diff` 为空（可复现）；
   - 受影响试点回归：BG8169 / 300673 输出不劣化；
5. 汇报：文件级改动清单 / 校验与回归结果 / 剩余风险与待办。

## 5. 边界与回退

- 方案被驳回 → 记录驳回原因，可缩小范围重提（引用原方案编号）；
- 执行中发现超范围新问题 → 停下，回到 §3 重新出方案；
- 规则发布状态翻转、`curated_by/reviewed_on` 回填 = 质控负责人人工动作（本技能最多给建议清单与影响面）；
- 新增审核叶子能力：三处登记（crwu-audit 路由注册表 + design §4 + skills/README）缺一不可，
  新叶子 SKILL.md 必须自带"仅经 crwu-audit 编排调用、禁止单独调用"门禁；
- KB 版本管理、钉钉知识库打通、`pull_全量画像.py` 基线脚本、技能安装机制均不在本技能范围。
