## 输入字段

报告审核记录的输入标识与必读字段如下。标识解析只按 [01-report-id-resolution.md](01-report-id-resolution.md) 执行。

| 信号 | 字段 | 用途 |
| --- | --- | --- |
| 报告标识 | `SeqNo`、`ObjectId` | 定位唯一记录 |
| 报告名称 | `F0000049` | 对象与业务弱结构化补充证据 |
| 报告形态 | `F0000056` | `report_form` |
| 业务大类 | `F0000065` | 业务类型主证据 |
| 评估目的 | `F0000064` | 业务类型主证据 |
| 评估范围 | `F0000066` | 范围与底层资产分类 |
| 对象大类 | `F0000119` | 资产类型分类 |
| 价值类型 | `F0000072` | 市场、公允、可收回、清算、残余等口径 |
| 法定性 | `F0000051` | 报告条款强制力 |
| 评估基准日 | `F0000067` | 时效性和冲突核查 |
| 报告文号 | `F0000092` | 披露一致性 |
| 监管归属 | `F0000082` | 国资覆盖层 |
| 金融标志 | `F0000124` | 金融/银行覆盖层 |
| 司法标志 | `F0000126` | 司法覆盖层 |
| 证券标志 | `F0000127` | 证券覆盖层 |
| 附件字段 | `F0000076` 等所有附件键 | 文件清单、下载和材料路径准备；文件名只是提示 |

`F0000020`、`F0000158`、`F0000178` 等风险等级/级次/状态只是背景或对照信号，不参与范围、资产、业务、方法或覆盖层路由。业务大类/评估目的为空时可读 `F0000049` 推断；名称仍含混时记录“画像歧义，需人工确认”，不猜测分发。

`F0000056` 的报告形态先于五个分发轴记录，并决定表述强制力：评估业务可使用评估结论等法定口径；咨询/估值文书使用参照口径，不得表述为“评估结论”或虚构结论有效期；矿业权评估同时继续识别 `asset_types[]=矿业权`。报告形态不能替代任何轴标签。

## route_profile

```jsonc
{
  "route_profile": {
    "identity": {
      "input": "用户提供的标识",
      "input_type": "SeqNo|ObjectId|material-package",
      "seq_no": "真实输入或查询返回值|null",
      "object_id": "用户提供或精确查询所得|null"
    },
    "report_form": "资产评估业务",
    "record_context": {
      "report_name": "F0000049 原值",
      "value_type": "F0000072 原值",
      "legal_status": "F0000051 原值",
      "base_date": "F0000067 原值",
      "document_number": "F0000092 原值",
      "recorded_risk_level": "F0000020 原值，仅作对照"
    },
    "scope_types": [],
    "asset_types": [],
    "business_types": [],
    "methods": [],
    "conclusion_method": null,
    "overlays": [],
    "review_risk_class": {},
    "material_gaps": [],
    "conflicts": [],
    "weak_structured": false,
    "confidence": {"overall": "high|medium|low", "note": ""}
  }
}
```

`scope_types[]`、`asset_types[]`、`business_types[]`、`methods[]` 和 `overlays[]` 中的每个分类标签必须具有：

```jsonc
{
  "type": "清算",
  "source": ["F0000064", "报告目的原文"],
  "evidence": ["企业清算", "为破产清算提供价值参考"],
  "location": ["record.F0000064", "评估报告·摘要·评估目的段(L60-68)"],
  "confidence": "high|medium|low",
  "review_required": false
}
```

`source/evidence/location` 是不可拆分的数组三元组：`source[]` 说明来自记录字段、报告文件或名称推断，`evidence[]` 保留实际字段值或原文，`location[]` 给出字段键或文件·章节/页/行号；文件未读取时用 `evidence=["未抽验（文件未读取）"]`、`location=[]`，不得伪造。企业价值范围下的 `asset_types[]` 另必须包含 `materiality: key|non-key|unknown`，并保留判定理由。字段直读或真实报告原文为高置信度；报告名称推断为中或低置信度；来源冲突、弱信号或 `materiality=unknown` 时 `review_required=true`。

## 文件级读取与溯源

评估目的原文、评估方法、结论方法及其位置只能来自真实读取的文件：

1. 源材料附件**只经单附件定向下载**取回：先 `crwu h3yun files list --schema <code> --id <ObjectId>` 取附件元数据，再对源材料件逐个 `crwu h3yun file get --id <FileId> --out <材料-源/…>`；复核件只记入《排除清单》、**永不下载**（阶段一门禁见 SKILL.md 步骤 2）。确认文件存在且字节数非零。
2. 先用 `file` 识别格式：旧 `.doc` OLE 可用 `textutil -convert txt`；`.docx` 读 OOXML；`.pdf` 用文本提取工具；`.xlsx/.xls` 用相应表格工具。先探测现有工具，不得凭印象宣称不可读。
3. 在文件中定位原文，为文件级字段回填数组 `source`、`evidence` 与 `location`。没有定位不得用于冲突定论。
4. 文件未下载或不可读时，字段显式标记 `未抽验（文件未读取）`，不填定位。

附件名只能标记为提示或待抽验，不能据此表述“已采用某法”。严禁从氚云字段、附件名、行业经验补写报告原文，或编造章节、页码、行号。

## 方法角色概要

`methods[]` 保留报告披露/采用的全部方法。每项严格使用 00 的通用标签 schema：canonical 方法写入 `type`，`source/evidence/location` 均为数组，并保留 `confidence/review_required`；方法项额外使用 `role=采用-作结论|采用-未作结论|测算-参考`。`conclusion_method` 单独保留结论所用方法并引用相同 canonical `type` 和证据结构。详细判定与多方法检查见 [05-method-classification.md](05-method-classification.md)。

## KB 装配输入

五轴 `route_profile` 是 router 的唯一画像契约。**装配清单不再由本仓工具生成**：命中某个轴标签后，下载清单 = 命中叶子 `references/01-kb-assembly.md` 中该轴的路径键（一级目录根 `request_kind=directory`/`recursive=true`，或明确的单文件路径）＋公共执行契约路径并集。

router 只负责把五轴画像映射成轴标签并选出 available 叶子；不得为兼容而生成旧画像键，也不得自行挑选叶子装配表以外的知识库文件。叶子按自身装配表声明的一级目录根，经 `crwu-dws` 递归实时下载该根下全部支持正文并准备材料；下载失败、空目录或不支持导出的节点记 capability gap，不静默忽略。

## Excel 隐藏数据隔离（工作版重建）

对下载的 `.xlsx/.xls`，在任何解析、提取或勾稽前制作工作副本。

**为什么必须排除**：Excel 中的隐藏 sheet / 行 / 列 / 折叠分组是**员工（检查人）手动隐藏**的，
表示其已明确不纳入本次审核。因此隐藏区**整体排除在审核范围之外**——Agent 处理到此处必须谨慎，
**绝对不能把隐藏区纳入审核范围**：不读取、不解析、不核对、不引用其任何单元格内容，不产生差异、
不产生意见、不写入证据值；对隐藏区**既不报错也不报漏**。

分两层执行，**默认永远是 H0**：

- **H0（默认 · 铁律）**：隐藏区禁读禁报。只允许读取"哪些 sheet/行/列被隐藏"这类**结构元数据**，
  用途是把隐藏区从工作版中剔除并输出忽略清单（只元数据，无内容值）。**唯一在 H0 内合法、且必须做的
  深化动作是「隐藏区引用审计」**：只解析**可见格公式里的引用坐标**，判断它是否指向隐藏行/列/隐藏工作表
  ——**只读坐标，不读隐藏区任何内容或公式**。
  **审计结果的去向（2026-09-16 用户口径）**：命中即把该**可见结果**记一条**「人工建议检查项」**
  （走 `manualConfirmationItems[]`、`review_required=true`，**不计入 `fail`、不进「需要处理的问题」**），
  写明"该可见结果的计算输入在隐藏区，须人工核对隐藏区公式与结果"（例如 `土地公允模式!P10` 的值由隐藏列 N 驱动）。
  **不得**因"引用了隐藏区"把它当成 AI 查出的问题，也**不得**据此定级或升级严重度——
  审核口径是**只要公式计算正确即可**。判据与边界：
  ① "公式计算正确"＝**可见区**勾稽/重算通过；**可见区自身**算错（勾稽不符、重算≠缓存值）仍按普通可见区
  缺陷定级出问题，与本条无关；
  ② 建议项**只为"被可见公式引用的隐藏区"出**；表内只是存在隐藏行/列、并不参与计算的不出（避免噪声）；
  ③ 仍**不得**读隐藏区的值或公式来"自证正确"，要读属 H1。
- **H1（唯一例外 · 须书面授权）**：**仅当委托人/审核负责人明确书面要求或授权**时，才可读取隐藏区内容。
  读取必须同时满足：① 只读经授权的最小范围；② 每条此类结论**单独成条**并**显式标注"经授权读取的
  隐藏区"**，禁止与可见区证据混同、禁止伪装成可见区发现；③ 在意见单与复核记录中留下授权出处。
  **未获授权时，涉及隐藏内容的疑点只能登记为「待人工复核事项」，不得进入结论、不得影响严重度。**
- 判定"隐藏区是否参与计算"**只看引用关系，不看隐藏与否**：隐藏列被可见公式引用 → 它是计算输入，
  不可复核；只有隐藏区内部自引用（可见区无引用）→ 可安全剔除。**不得因"被引用"就把隐藏列并入工作版
  或纳入审核范围**（那会重新破坏 H0）。

- raw 原件保留不动，只由编排层持有；隐藏状态无法判定时按隐藏剔除，并记录"隐藏状态未知 · 已剔除"。
- 只能用**重建法**：新建簿并只复制**可见 sheet × 可见行 × 可见列**的值与格式。禁止用 openpyxl
  `delete_rows`/`delete_cols` 逐行列删除（会残留维度元数据）。折叠分组（`outlineLevel>0` 且组头
  `collapsed=True`）**视同隐藏**，一并剔除。
- **缓存值优先**：单元格有缓存值（`data_only=True`）就写缓存值，**仅当无缓存值**才写公式串。
  重建簿不会被 Excel 重算，写公式串会让后续 `data_only=True` 读回 `None`，把"公式未重算"误读成
  "数据缺失"（曾据此误报"评估结果列全空"）。
- **「值不可得」≠「数据缺失」**：无缓存值且为公式（含引用外部工作簿）的格，按表计数登记为
  「值不可得（未重算/外部引用）」元数据（不含内容值）；后续只能**如实声明该格取不到值**，
  **禁止**表述为"空白／缺失／未填"，也不得据此产生差异或下结论。
- **输出名唯一 + 来源可追溯**：同名不同版本（如定稿与送审稿同名）必须消歧（追加来源目录后缀），
  盘点须记录每份材料的来源子目录（`stage`）与工作版路径一一对应，**禁止静默覆盖**（曾因送审稿
  覆盖定稿，把"使用状况"误判为"自用"）。
- **不得改变格式语义**：逐格复制 `number_format`，数值／日期语义与原件一致；遇"疑似被日期化的
  数值列"，结论前必须回 raw 原件核对格式（不得把原件问题与重建问题混为一谈）。
- **遍历边界按"有值格"定，四层各归各的**（原件常见游离的 `value=None`、只有样式的"格式格"，
  如整列刷格式残留；它们会让任何按声明用区遍历的工具退化成百万行扫描）：
  **① 扫描边界** = **有值**格（缓存值 ∪ 公式串）的精确集合，不按声明用区扫矩形、不设阈值；
  **② 内容边界** = 同一集合的 max 行列（即 `stats.maxRow/maxCol/visibleRows` 的口径）；
  **③ 异常提示** = 声明用区与有值区相差 >1000 行/列 → 记入 `材料盘点.json` 的 `sheetAnomalies[]`
  （属**可见区表格规范缺陷**，只提示、**不改变遍历、不改变审核范围**）；
  **④ 规模护栏** = 单表有值格 >2,000,000 → 记 `capabilityGaps` 并跳过该表，**其余表继续**（不静默截断）。
  未触发③的表若声明用区与有值区不一致，逐个在 `stats[].declaredSpan` 留痕，不丢信息。
  注意：**"空洞大"≠"表大"**——按空洞裁会漏掉"游离格落在阈值以内"的病态表，故④按规模裁。
- 保存后重新打开工作版，验证隐藏区数量为 0。失败则按重建法重做；仍残留则挂起，不继续审核。
- 工作版剔除行列后坐标会收缩，而公式串仍保留 raw 坐标。公式／引用／合计范围类勾稽以 raw 坐标为准，
  只读可见单元格；纯数值勾稽可在工作版执行。
- **交付物中的 Excel 证据定位必须使用 raw 原件坐标**：最终意见、AuditResult、HTML、复核对照和
  审核记录中的 Excel `locator`，必须写原件的工作表名与单元格／区域坐标；**工作版坐标仅限审核执行内部使用**，
  不得作为对员工或复核人员的证据定位下发。工作版因剔除隐藏行列导致坐标收缩时，形成 finding 前必须按重建时的
  行列对应关系**映射回原件坐标**，且只允许映射、引用 raw 可见区；不得借坐标回映读取或披露隐藏区内容。
  **无法可靠映射**时，**不得下发该定位**，也不得猜测原件坐标；应将该项降为「待人工确认事项」并记录
  `capability gap`，直至取得可验证的原件定位。
- **任何"未列示／缺失／为空"类结论下发前，必须回到 raw 原件（定稿）逐条复读确认**——不得凭工作版、
  更不得凭同名送审稿下此类结论（同一项目曾因此复发三次）。
- **非单元格证据（媒体/页眉页脚/批注/形状/图表）不得据工作版判断，必须走「媒体证据通道」**：
  重建法只复制单元格值与 `number_format`，**必然**丢弃 `xl/media/`、`word/media/`、`xl/drawings/`、
  页眉页脚（`xl/worksheets/*.xml` 的 `headerFooter`）、批注（`xl/comments*.xml`）与形状/图表。
  编排层由 `scripts/prepare_materials.py`（内部调用 `scripts/media_extract.py`）把媒体**导出**到
  `<案例>/媒体证据/`，并写放行清单 `<案例>/媒体索引.json`；叶子按下述口径消费：
  ① **"工作版中不存在" ≠ "原件中不存在"**——对媒体类证据，只看工作版（甚至只看 raw 的单元格）
  都会得出错误的"为空/缺失"；
  ② 判读媒体**只经放行清单**：`媒体索引.json` 的每条含 `mediaId`、`kind`、受控 `locator`
  （如 `1-2市场案例位置图!图片#1（锚点 4:4）`、`<文件名>#第<N>页图片#<序号>`、
  `评估说明.docx!第<段落号>段图片#<序号>（前文：…）`、`<文件名>（整图）`）、`localPath`
  （案例内相对路径）、`sha256`。**叶子不得自行解析 raw 原件包**（raw 只由编排层持有）；
  ③ **判读交宿主多模态读图**（DeepSeek Harness 的 `read_image` 等）；读不到（宿主无视觉能力、
  图片损坏、媒体未导出）只能出「**未核验**」，**严禁**表述为"为空／缺失／未列示"——
  **未核 ≠ 缺失**（真实失效 2026-302150-LX9757-BG8677：`MKT-004` 判"可比实例位置图为空、
  询价截图缺失"，而原件 `04评估计算表.xlsx` 实有 26 个媒体对象、位置图带 4.6/5.4/3.8 km 标注）；
  ④ **H0 同样适用于媒体锚点**：锚点落在隐藏 sheet / 隐藏行 / 隐藏列上的媒体**不导出、不定位**，
  只在盘点里记数量（`hiddenSkippedCount`，无内容、无 locator）；锚点不可判定（`absoluteAnchor`、
  未被任何 drawing 引用的部件、图表、页眉页脚）与**隐藏结构不可得**时一律**保守不导出**并记
  `unresolvedReasons[]`（fail-closed）。媒体内容本身若呈现隐藏区内容，属 H1，须书面授权；
  ⑤ 盘点汇总在 `材料盘点.json` 的 `nonCellEvidence`（`filesWithMedia` / `rawMediaCount` /
  `exportedMediaCount` / `hiddenSkippedCount` / `unresolvedCount`）与逐件的 `mediaEvidence`；
  `rawMediaCount` 与 `hiddenSkippedCount` **只记数字**，不含内容与定位。
- raw 原件只由编排层持有，叶子/下游只接收工作版路径**与编排层导出的媒体证据副本**（`媒体索引.json`
  放行的 `媒体证据/` 文件）。唯一其他例外是公式/引用坐标核查可对 raw 可见区做限定只读访问。
  叶子整簿读 raw、读 raw 隐藏区或读仍含隐藏区的工作文件时立即阻断并记录违规。
- **读不到 ≠ 材料缺失**：因缺依赖（`openpyxl`/`python-docx`/`pypdf`/`xlrd`）、无文本层（扫描件）、
  加密或格式不支持而读不到的材料，一律记 `capability gap` 并**如实声明"该件本次未核"**；
  **禁止**表述为"材料缺失/未提供"，更不得据此产生差异或结论。脚本每次运行都会汇报缺失依赖。
  `.docx` 在缺 `python-docx` 时自动回退 `textutil`（评估说明/报告正文多为 `.docx`，读不到会直接
  改变结论），回退会在盘点中标注。
- **图片/扫描件同理**：本机不保证 OCR 与渲染能力（`tesseract`/`pdftoppm`/`soffice`/`PyMuPDF` 可能
  全缺），媒体判读只能由**宿主多模态**完成。宿主无视觉能力、图片不可读或媒体未导出时，逐条写
  `scope.notCheckedItems`（`reasonCode=unreadable|unsupported`）并给 `requiredAction`，
  **不得**计入"缺失材料"，也不得据此下"为空/缺失"结论。
- **压缩包必须先解压再审核**：盘点时遇 `.zip/.tar/.tar.gz/.tar.bz2/.tar.xz/.tgz` 等归档，**必须先解压，再对解压产物实施审核**——归档内的测算底稿、明细表与源材料同等对待（同样提取文本、重建工作版、执行隐藏区隔离）。**不得把归档登记为"未解压"就跳过**（真实案例中一个归档内的"土地使用权-工业拟变更住宅-测算底稿"因此长期未被审核，属潜在漏检）。
  - **落点**：解压到 `<案例目录>/解压/<归档名>/`，**源材料目录零写入**；盘点记录 `originArchive` 指向来源归档，可追溯，避免"解压产物来源不明"。
  - **阶段一隔离门禁优先于解压**：归档内含复核记录类文件（复核/质控/外审/答复/审核意见等）时**不解压该条目**，只记名字，不得让其内容进入阶段一工作集。
  - **安全**：拒绝绝对路径、`..` 越界（zip-slip）与符号链接条目；条目数与解压总量设上限，超限记 capability gap，不静默放过。
  - **文件名编码**：zip 内中文名常为 GBK 且未置 UTF-8 标志位，默认按 cp437 解码会得到乱码文件名——**必须按 GBK 重解码**，否则连"这份材料是什么"都无法判断。
  - **不支持的格式**：`.rar/.7z` 等在本机无 `7z/unar` 时，记 capability gap「该件本次未核」并如实声明，**不得记作"材料缺失"，也不得静默跳过**；嵌套归档限深解压（默认 2 层）。
- **实施（技能自带脚本，随技能安装）**：`scripts/prepare_materials.py`
  （`python3 scripts/prepare_materials.py --case <案例目录>`）产出 `材料盘点.json` / `媒体索引.json` /
  `提取/` / `工作版/` / `媒体证据/`；媒体抽取通道在同目录 `scripts/media_extract.py`
  （xlsx 锚点、docx 段落序、`.doc` 经 `textutil` 中转、PDF 内嵌图、独立图片；H0 与 fail-closed 见上）。
  **阶段二复核件**用 `--src <案例>/复核-人工 --label 复核` 复跑（产出 `复核盘点.json` /
  `复核媒体索引.json` / `媒体证据-复核/`），**禁止覆盖阶段一冻结的 `材料盘点.json`**。
  契约测试 `scripts/test_prepare_materials.py` 与 `scripts/test_media_extract.py` 覆盖缓存值优先、
  隐藏区零泄漏（含折叠分组与**媒体锚点**）、同名消歧、「值不可得」登记、缺依赖不静默空返、
  源目录只读、格式保留、媒体导出与阶段二产物隔离。

## 材料缺口与降级

缺失材料、未抽验字段、未注册标签或 pending 能力按标签分别写入 `material_gaps[]`。不可用的单个技能不得导致其他 available 技能短路；不得以“无能力”空返，应附非审核结论的能力缺口说明。
