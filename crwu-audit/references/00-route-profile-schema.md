## 2. 弱结构化兜底
- 业务大类/目的为空（基线约 700 条）→ 必须读 `F0000049` 名称推理 canonical 角度；
- 名称含混推不出 → 输出"画像歧义，需人工确认"，**不猜测分发**。

## 3. route_profile 画像 schema（分发输入，JSON v0.1）

每个字段带 `source`（字段 / 名称推断 / 附件名 / 材料抽验）与 `confidence`（高/中/低）。

    "business_risk_class": { "class": "B", "hits": ["B5"], "unknown": [],

## 4. 置信度与来源标注规则
- 字段直读 → 高；名称推理 → 中/低（须标 source=名称推断）；
- 方法未确认前不得在分发结论中使用"已采用某法"的强表述；
- 三条来源（字段/名称/附件名）冲突 → 交 02 冲突检测（ROUTE001–004）。

## 5. 路由前置输入与文件级提取（增补）

- **显性输入前置**：报告名称 F0000049、风险等级 F0000020（先验/一致性锚点，不直接采信）；
- **文件级提取（路由阶段，不限字段）**：评估目的原文（比对 F0000064）、评估方法（读方法章节，附件名仅提示）；
- **复杂度档**：对象=单项资产 → 常规流；对象=企业价值类（股东权益/企业资产负债/资产组合/资产组）→ 复杂流。
- **方法必须分层记录**：`methods[]` = 报告**披露/采用的方法集合**（可为多个，逐一标注 role：
  `采用-作结论` / `采用-未作结论` / `测算-参考`）；`conclusion_method` = **结论方法**（如 市场法）。
  **role 判定以报告"选用的评估方法/评估方法选择"口径为准**：凡报告明确"选用/采用"的方法即使结论未取，
  也是"采用-未作结论"（其结果通常并列列示、须做差异分析），不得反推为"参考/未采用"；仅在报告明示为
  辅助测算/验证时才标"测算-参考"。多方法不得压成单一"结论方法"，附件文件名仅作提示，不作依据。
- **多方法审核点（叶子方法专项执行）**：是否披露全部采用方法、是否说明结论方法选取理由、
  两法结果差异是否分析（差异大须解释）、报告/说明/明细表方法口径是否统一。

```jsonc
{ // route_profile 增补字段（与 §3 合并输出）
  "inputs": { "report_name": "…", "risk_level_record": "C", "risk_level_source": "F0000020-先验/对照" },
  "purpose_file": "为…提供价值参考（报告原文）",
  "methods": [
      { "method": "市场法", "role": "采用-作结论", "source": "文件-摘要/方法章节", "confirmed": true },
      { "method": "收益法", "role": "采用-未作结论", "source": "文件-说明-收益法章节(结果并列列示)", "confirmed": true }
    ],
  "conclusion_method": "市场法",  // 结论方法：对应 methods[] 中 role=采用-作结论 的那一个
  "complexity": { "object_scope": "企业价值", "flow": "complex",
                    "reason": "企业价值→需财务异常/方法专项/证据验证",
                    "required_modules": ["financial-anomaly","income-approach","asset-approach","evidence-validation"] }
}
```

## 6. 路由沉淀字段与依据出处（路由只沉淀字段，不做冗长说明）

路由画像只**沉淀字段与结论性标记**，展开说明交给叶子/兜底报告；本文档 + references/01/02/03 是字段唯一来源。

| 层 | 字段 | 依据出处要求 |
| --- | --- | --- |
| A 记录字段层 | 报告名称 F0000049；风险等级 F0000020（先验/对照）；形态 F0000056；大类 F0000065；目的 F0000064；范围 F0000066；对象 F0000119；价值类型 F0000072；法定 F0000051；归属 F0000082；标志 F0000126/0127/0124 | 字段键本身即出处（record.schema） |
| B 文件级提取层 | `purpose_file`（评估目的原文）；`methods[]`（含 role）；`conclusion_method` | **必须带依据出处 `loc`（文件·章节/页/行号）**；无出处 → 标 unverified，不得用于冲突定论 |
| C 派生层 | `business_risk_class`（03）｜canonical 角度（01）｜`regulatory_overlays`（02）｜`complexity`（§5）｜`weak_structured` | 引用其判定文件与命中条款 |

```jsonc

{
  "purpose_file": { "text": "…为资产处置（转让）经济行为提供价值参考", "loc": "评估报告-摘要·评估目的段(L60-68)" },
  "methods": [
    { "method": "市场法", "role": "采用-作结论",   "source_loc": "报告摘要评估方法行(L73)/说明·方法章节" },
    { "method": "收益法", "role": "采用-未作结论", "source_loc": "报告摘要评估方法行(L73)/说明·结论章节(L1072)" }
  ],
  "conclusion_method": { "method": "市场法", "loc": "报告评估结论行(L74)/说明·最终结论(L1245)" }
}
```

## 6.1 文件级抽验的执行前置（下载→转换→定位）与反拟造红线

B 层字段（评估目的/评估方法/结论方法 + loc）**只能来自真实读取的文件**，前置链路必须走完才有权回填：

1. **下载**：`crwu h3yun file download --schema <code> --id <recordId> --out <dir>`，确认文件实体存在（ls/字节数）；
2. **Excel 脏数据硬删除（下载后、任何解析/提取/勾稽前必做）**：对下载的 `.xlsx/.xls` 制作工作副本，
   把**用户手动隐藏的数据整体删除**（隐藏 sheet / 行 / 列 / 折叠分组）——隐藏内容=脏数据，不得进入
   workspace 工作版、不得被后续任何解析/勾稽/LLM 读取、引用或输出；
   - raw 原件保留不动，删除只发生在工作副本；
   - 识别隐藏结构（sheet_state / hidden 行列 / 分组折叠级别）属**结构元数据**，允许读取用于定位删除；
     隐藏区域单元格**值禁读禁输出**（与 datacheck H0 铁律一致）；
   - 无法判定隐藏状态 → 按隐藏处理删除，并记录“隐藏状态未知 · 已删除”；
   - 删除完成后校验工作版隐藏区数量=0（结构元数据核）；校验不过 → 阻断并报告，不得继续；
   - 处理后工作版仅含可见数据；合计/勾稽只按可见区核；
   - **数据隔离（硬性）**：含隐藏脏数据的 **raw 原件默认只由编排层持有，任何后续子技能/模块一律
     不得读取**——叶子/下游只能使用已删除隐藏数据的工作副本；需要表格/报告时一律传**工作版路径**，
     发现子技能读取 raw 原件或仍含隐藏区的文件 → 立即阻断并记违规；
3. **转换**：先用 `file` 识别——旧版 .doc（OLE，magic `d0cf11e0`）→ 本机 `textutil -convert txt <doc>`；
   .docx → unzip/xml 或现成工具；.pdf → 文本提取工具；.xlsx → openpyxl 等。
   **先 `which`/探测本机可用工具再下结论**，禁止仅因"好像没有工具"就停在"待抽验"；
4. **定位回填**：grep/read 得到 文件·章节/页/行号，命中原文后才可填 `text + loc`。

**反拟造红线**：评估目的/评估方法/结论方法及其 loc **严禁**凭氚云字段、附件文件名、行业经验"补写"
原文或编造章节/行号；文件未下载/不可读 → 对应字段显式标 **未抽验（文件未读取）**，不填 loc，
不得用于冲突定论，不得装作已审。

**数据隔离红线**：删除动作只在**工作副本**进行；含隐藏脏数据的 raw 原件不向任何子技能开放，
叶子/下游一律读工作版路径；违反隔离（子技能直读 raw/原件）→ 阻断并记违规。

## 7. 子技能未实现 → 路由级兜底简要报告

触发：分发命中技能状态为 🅿️/⏳（暂未实现），或大方向未命中且无 A 级依据。
行为：**不允许"无能力"空返或静默跳过**——输出一份路由级兜底简要报告
（文件名建议 `审核意见.<项目ID>.路由兜底.md`）：

```markdown
# <项目名称> —— 路由级简要说明（依赖子技能暂未实现）
> 生成：crwu-audit 路由｜时间｜说明：**本单为路由初步说明，不构成审核结论**

- 定位：SeqNo｜报告名称｜评估基准日｜记录风险等级
- 画像摘要：报告形态｜canonical 角度｜对象（大类×范围：**单项资产 / 企业价值…**）
  复杂度档（常规流 / 复杂流）｜价值类型｜监管覆盖层｜机构业务分类(A/B/C + hits)
- 评估目的：<原文>　【依据出处：文件·章节/页】 —— 若未实际读取文件，此处**必须**显式填
  `未抽验（文件未读取）`，禁止留空或装作已审
- 评估方法：<方法列表 {方法, role} + conclusion_method>　【依据出处：…】 —— 同上，
  未读取文件 → 显式 `未抽验（文件未读取）`；**严禁凭字段/附件名/经验拟造原文或行号（拟造=红线）**
- 说明：对象为**单项资产（常规流）** / **企业价值（复杂流，需财务异常/方法专项/证据验证）**；
  **依赖子技能 `crwu-audit-<x>`（状态：待实现 P1）暂未实现** → 本单仅为路由初步说明，
  不构成审核结论；待子技能实现后重跑，或由人工按上述画像复核。
```
