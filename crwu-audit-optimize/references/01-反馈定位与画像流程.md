# references/01 · 反馈定位：单子画像 → 审核规则 / 业务路线 / 资产类型

| 版本 | v0.1 | 状态 | 定稿 | 维护 | crwu-audit-optimize |
| --- | --- | --- | --- | --- |

> 目标：把用户的模糊反馈（"这个单子审得不对/缺了某类审核"）变成**可证伪的定位结论**：
> 该单子 现行路由路径 + 实际命中规则集 + 库内应有而缺失的规则段。所有定位结论必须附证据
> （references/02 §1），禁止凭印象下结论。
>
> 文内『KB/知识库』= 钉钉知识库（crwu-dws 实时下载源）。本流程需要读知识库治理/目录/规则正文时，一律经
> crwu-dws 按库内层级路径实时下载后只读核对（出处=本次下载文件:行号+exportedAt）；下载不可得 → 显式报告，
> 目录缓存不能提供正文。`kb_tool.py validate` 为维护侧引用/实时协议校验工具（§3）；
> 装配面不再由工具生成，读叶子 `references/01-kb-assembly.md` 的路径键即可。

## 1. 输入与来源

| 输入 | 来源 | 说明 |
| --- | --- | --- |
| 单子标识 | 用户口述/文号（BG8xxx、LX…）或材料目录 | 材料包目录约定由部署环境注入 |
| 历史审核产物 | 本地审核意见单（`审核意见.*.json/md`）、路由路径、适用规则集快照 | **现状基线**：真实命中面 vs 期望 |
| 校准/回测案例 | KB `00-总纲/治理/校准案例记录`（案例 A/B）、`回测报告-真实案例覆盖.md` §5 | 已闭合检查点（R）与缺口（G）清单 |
| 路由/装配现状 | crwu-audit `SKILL.md` §3 + `references/07-skill-registry.md`；叶子 `references/01-kb-assembly.md`（技能→知识库寻址键）；知识库 `00-总纲/目录地图` | 画像→技能/知识库层级路径 |

## 2. 画像五维提取（口径与 crwu-audit references/00 一致）

1. **报告形态**：评估报告 / 咨询报告 / 估值报告 / 其他（首判，决定条款强制力与参照口径）；
2. **对象大类**：委托合同/报告对象章节 → 02-资产类型 子目录（房地产/企业价值/无形资产/机器设备/组合…）；
3. **业务主线（一级业务标签）**：评估目的原文 → `01-业务路线/` 一级目录（资产经营/交易与处置/财务报告/融资与债务/投资与资本运作/税务与历史确认/司法清算与补偿/咨询复核与其他）；历史行为词（转让、并购、增资、清算、抵押、司法、减值测试…）只作**命中信号**映射到上述一级业务，子业务在父级内选用，不产生独立标签；
4. **方法**：附件文件名提示 + 报告方法章节抽验（多方法逐一列 role，禁止凭附件名定论）；
5. **监管覆盖**：国资/证券/司法/金融标志 → 04-监管覆盖 对应装载。

产出一份画像（供人工/脚本比对装配面），形如：

```json
{
  "dims": { "object_type": ["不动产评估"], "method": ["市场法"],
            "scenario": ["经营性物业出租"], "stage": ["报告"] },
  "modules": ["M-市场法", "M-报告披露", "M-基准要素一致性", "M-数据校对"]
}
```

（stage 不作硬过滤，由叶子按材料分区判断。画像字段口径以 crwu-audit `references/00-input-and-route-profile.md` 为准；本仓不再持有画像示例文件。）

## 3. 机器辅助定位（标准三步）

```bash
# ① 现行命中面：读路由结果 + 命中叶子的装配表路径键
#    crwu-audit 路由输出（画像五维 + 路由路径 + 适用规则集快照）
#    命中叶子 references/01-kb-assembly.md → 一级目录根 / 单文件路径键
# ② 库内是否已有对应规则/清单段：按路径键经 crwu-dws 实时下载正文后核对
#    dws 按库内层级路径取正文（本次工作集，清单外零下载）
# ③ 漂移/一致性线索
kb_tool.py validate --skill-root <源仓>/skills --skill-root <运行时真身>/skills
#    引用卫生（旧树残留 / KB/… 省略号 / 已废止的 KB/<rel> 与 CRWU_KB_ROOT 字面）
#    + "三不写" lint（禁知识库名称 / 禁本地正文路径字面 / 禁 nodeId 常量）
python3 skills/crwu-audit-skill-maintainer/scripts/check_audit_skill_mappings.py \
  --repo-root . --catalog <最新 DWS 目录快照>
#    registry ↔ classification ↔ 真实技能目录 ↔ 最新知识库目录 是否一致
```

## 4. 覆盖缺失模式："缺 XX 文档对 XX 文档的审核"

把反馈拆成 **(形态对 × 对象 × 业务 × 阶段/分区)** 组合，例如：

| 用户反馈 | 拆解 | 判定路径 |
| --- | --- | --- |
| 缺"报告↔测算明细表"勾稽 | 已有分区（报告/评估说明/测算明细表）CHK-MKT-013 等 | 若已覆盖→反馈为内容问题（A/D）；未覆盖→清单漏项（A） |
| 缺"底稿↔报告"跨文档一致性 | 现无该分区/模块 | M-数据校对扩分区或新增 CHK 段（A）＋调度总纲分区表（契约） |
| 缺"某业务路线（如司法-抵债资产）× 不动产"审核 | 路由注册表该组合空/🅿️ | B：先查 01-业务路线 与 02-资产类型 精编现状 → 新建叶子候选（三处登记）或先扩词表+装配 |
| 缺"咨询文书×无形资产成果转化" | 报告形态=咨询 → 参照口径族 | C/B：词表 report_type/角度登记 → advisory 大方向或参照口径清单 |

判定三步：
1. 该组合**应命中**现有路由吗？应命中却兜底 → 词表/路由/装配范围问题（C 或 B，小改）；
2. 命中后**库内有对应 RULE/CHK 段**吗？没有 → 内容缺口（A：补精编条目或清单项，走入库规范四步）；
3. 命中且库内有、但真实意见仍对不上 → 检查点文字/算法/执行问题（A 或 D）。

每个缺口在方案里给出**建议最小新增物**（新 CHK 项 / 新模块 / 新分区 / 新画像取值 / 新叶子技能），
不要一上来就建议新建技能——优先最小落点（先在 references/00 §2 找已有落点复用）。

### 4.1 与路由兜底提案衔接

crwu-audit 路由兜底时会自动产出《待建子技能提案》卡（`crwu-audit/references/04`）：候选技能名 /
定位职责 / 需要审核什么 / 现成依据段 / 内容缺口 / 前置登记 / 优先级，并附路径键与下载证据。本技能 B 桶
诊断**直接以该卡为输入**（用户批注即需求补充）：把卡细化成《优化方案》——新 SKILL.md 骨架、词表登记行、
内容缺口补精编任务、三处登记与拷贝同步；确认门禁与验收基线不变（references/00 §4）。

## 5. 证据清单（方案必须引用其一以上）

- crwu-audit 路由输出（画像五维 + 路由路径 + 适用规则集快照）与命中叶子的装配表路径键；
- 经 crwu-dws 实时下载的规则段落正文（含库内层级路径 + 下载文件实测锚点行号 + exportedAt）；
- 历史审核意见单中的路由路径与适用规则集快照；
- 回测报告 §5 的检查点重映射（R/缺口 G 编号）；
- `kb_tool.py validate` 输出（error/warn 明细）。
