# references/00 · 优化规范与文件落点（改动类型 → 唯一落点）

| 版本 | v0.2 | 状态 | 2026-09-07 更正（技能三处拷贝：源仓 / .skills-manager（=`~/.dsh` 软链目标）/ .workbuddy 实际生效） | 维护 | crwu-audit-optimize |
| --- | --- | --- | --- | --- |

> 本文件把"审核能力族 + 知识库"的维护规范固化成**改动类型→唯一落点**地图：优化动作只许动对应落点，
> 其余文件禁止顺手改；改完必须完成 §4 验收基线。改 crwu-audit 族任何技能前，另须先读
> `crwu-audit/references/99-维护说明.md`。

## 1. 常量与三处拷贝（2026-09-07 更正，见 OPT-2026-09-07-01 E7）

- **KB 根常量 CRWU_KB_ROOT = `~/.crwu/knowledge/knowledge-base`**（`~/.crwu/knowledge` 只是父目录，不作引用根）。
  技能/文档引用一律写该根下完整路径，禁止省略号、禁止个人绝对路径；校验=`kb_tool.py validate --skill-root …`。
- **技能三处拷贝必须同版本**：① 源仓 `crwu-ai/skills/`；② `~/.skills-manager/skills/`
  （`~/.dsh/skills/` 是软链指向此处——改 `~/.dsh` 路径即改它）；③ `~/.workbuddy/skills/`
  （**实际生效目录**，agent 运行时读取）。每轮改动后三处两两 `diff -r` 为空才算同步完成。
- **工具**：`kb_tool.py`（源仓 `tools/kb/`；子命令 index/validate/resolve/query/release/assemble/extract/selftest；
  可执行路径由部署环境注入；无工具时按装配表手工装载，但**方案必须附手工证据**）。
- 本技能 references 随技能安装，内容自带根常量，不回指 skills/README（该文件不装到 agent）。

## 2.1 KB 变更的同步义务（索引 / 装配表 / 目录地图 三件套）

> **铁律：KB 有任何内容或结构变更，`kb-index.jsonl` 必须与变更同批重跑刷新**（其 `_meta.files`
> 存每文件 hash，过期即 `validate` 报 error）。装配表/目录地图只在"路径/指针/装配范围"受影响时改，
> 但**禁止出现"KB 已改、索引没刷"或"文件已动、指针没跟"的中间态**——本流程收尾以
> `validate` error=0 ＋ 受影响装配两跑一致 为准。

| KB 变更类型 | 必做同步 | 说明 |
| --- | --- | --- |
| 条目正文/判定要点/dims/modules/标题（同文件内编辑） | ① `kb_tool.py index` 重跑 ② validate ③受影响装配两跑 | 装配表指针不受影响，不用动 |
| 同文件新增条目 | ① index 重跑 ② 批次 README/进度总表对应行（条目计数/段位变化时） | 新增条目须先登记词表取值（若用新标签）；`### <id>` 锚点唯一 |
| 新增/改名/移动/删除 KB 文件或目录 | ① 受影响叶子的 `references/00-KB装配表.md`（逻辑指针行）② KB `00-总纲/目录地图.md`（画像→目录行）③ 相关文档内引用文本 ④ index 重跑 ⑤ validate | 改名前先 grep 全库引用（装配表/SKILL/治理文档），一个不漏 |
| 装配范围/模块标签体系变化（某技能该装哪些清单与规则段） | ① 对应叶子 `references/00-KB装配表.md` ② 词表登记（若模块/取值变化）③ index 重跑 ④ validate | 影响"命中/排除"语义，须重跑受影响画像两遍验证 |
| 发布状态翻转（A 待发布→已发布，回填 curated_by/reviewed_on） | ① index 重跑（release 列才更新）② 待发布清单同步 | **翻转动作=质控负责人人工执行**，本流程只读、只提醒"发布后必须重跑 index" |
| KB 引用路径/文件名出现在技能正文中（SKILL.md） | ① 技能正文同步 ② 装配表同步 ③ validate --skill-root | 个人绝对路径与 `KB/…` 省略号禁止 |
| 校准/回测结论更新（案例覆盖、缺口 G） | ① `校准案例记录.md`/`回测报告-真实案例覆盖.md` 回填 ② 受影响清单/规则条目若改→按首行"index 重跑" | 回测与规则互为证据链，不同步=下次优化失去基线 |

## 3. 红线（不许绕过）

1. **未出方案、未经用户确认，不动任何文件**（含 KB 内容）；
2. 不产审核判断、不出正式/试点审核意见（那是 crwu-audit 流程）；
3. 不翻转发布状态、不回填 curated_by/reviewed_on（质控人工）；
4. 不把规则/清单正文复制进技能（技能=流程+指针+算法，正文=KB）；
5. 编号唯一性以定义锚点为准（正文区间引用不算重复）；
6. 个人绝对路径、`KB/…` 省略号、旧树目录名（01-规则库/02-审核清单库/执业准则-*/06-素材库-L2 等）一律禁止出现；
7. SKILL.md ≤300 行；改 crwu-audit 族技能前先读 `crwu-audit/references/99-维护说明.md`；
8. 每次改动同步三处拷贝（源仓 / `.skills-manager`（=`~/.dsh` 软链目标）/ `.workbuddy` 实际生效），登记三处（design/README/CHANGELOG）。

## 4. 验收基线（每次优化完成后必须全过）

```bash
# 1) 改了 KB 规则文件才需要重建索引
kb_tool.py index
# 2) 三方校验：error 必须为 0（warn 相对基线不得增加）
kb_tool.py validate --skill-root <源仓>/skills --skill-root <运行时>/skills
kb_tool.py validate --skill-root ~/.crwu/knowledge/knowledge-base   # 顺带扫 KB 内引用
# 3) 装配可复现：受影响示例（含本单画像）两跑 diff 为空
kb_tool.py assemble --profile <画像>.json --out a.md && kb_tool.py assemble --profile <画像>.json --out b.md && diff a.md b.md
# 4) 试点回归：BG8169 / 300673 输出不劣化（见 KB 回测报告 §5）
```

通过判据：error=0；装配两跑一致；受影响试点无劣化；拷贝 diff 空；登记完成。任何一条不过 → 回到方案修订。

## 5. 顺序纪律（确认后的执行顺序）

落点文件 → 引用它的上层文件 → 运行时拷贝同步（diff 核对）→ 登记（词表/路由表/design/README/CHANGELOG/批次 README）→
index/validate → 装配两跑 → 试点回归 → 汇报（文件级清单 + 校验结果 + 剩余风险）。
