## ✨ Overview

This repository gathers the agent skills I use day-to-day across Claude Code, Codex, DeepSeek Harness, and OpenCode — some authored here, some referenced from the community. Each skill is self-contained and can be symlinked into a supported agent's skills directory.

- 🧩 **Two skill types** — custom (authored, with `SKILL.md` + `skill.json`) and referenced (external, with `install_reference.md`)
- 🔗 **Symlink-friendly** — install once, update everywhere
- 🛠️ **Self-hosting tooling** — project skills that manage the repo itself
- 🌐 **Bilingual** — English & 中文 docs kept in sync

## 🗂 Directory Structure

```
skills/
├── README.md                # You are here
├── Agents.md                # Agent conventions
├── agent-config/            # Global agent conventions (symlinkable)
├── .agents/skills/          # Repository-maintenance skills
│   └── <skill-name>/
│       └── SKILL.md
├── github/                  # GitHub sources (not yet integrated)
│   └── <user>/<repo>/
│       └── install_reference.md
├── vendor/                  # Upstream skill collections (read-only)
└── skills/
    └── <category>/
        └── <skill-name>/
            ├── SKILL.md             # Custom skill main file
            ├── skill.json           # Custom skill metadata
            ├── helpers/             # Helper scripts (optional)
            └── install_reference.md # Referenced skill source info
```

## 🧩 Skill Types

### Custom Skill (Full)

Skills I create and maintain, containing:

- **`SKILL.md`** *(required)* — with frontmatter, defines the skill's functionality and triggers
- **`skill.json`** *(required)* — generated by `/create-skill-json`
- **`helpers/`** *(optional)* — helper scripts, templates, etc.

<details>
<summary><b>SKILL.md format</b></summary>

```markdown
---
name: skill-name
description: One-line description of the skill's purpose and trigger
metadata:
  version: 1.0.0
---

# Skill Title

Detailed description of the skill's functionality, usage, and notes.
```
</details>

<details>
<summary><b>skill.json format</b></summary>

```json
{
  "version": "1.0.0",
  "name": "category/skill-name",
  "title": "skill-name",
  "aliases": ["skill-name", "category/skill-name"]
}
```
</details>

### Referenced Skill (External)

Skills maintained by others (GitHub, npm, etc.). No `SKILL.md` or `skill.json` needed — only:

- **`install_reference.md`** — describes the source and installation method

<details>
<summary><b>install_reference.md format</b></summary>

```markdown
# Skill Name

- **Source**: <url>
- **Type**: git | npm | other

## Install

Install command...
```
</details>

## 📦 Installation

```bash
# Custom skill: choose an agent's global skills directory
mkdir -p ~/.claude/skills ~/.codex/skills ~/.dsh/skills ~/.opencode/skills
ln -s "$(pwd)/skills/dev/my-skill" ~/.claude/skills/my-skill
ln -s "$(pwd)/skills/dev/my-skill" ~/.codex/skills/my-skill
ln -s "$(pwd)/skills/dev/my-skill" ~/.dsh/skills/my-skill
ln -s "$(pwd)/skills/dev/my-skill" ~/.opencode/skills/my-skill

# Referenced skill: follow the instructions in its install_reference.md
```

> **Tip:** Use absolute paths for symlinks — relative paths break when the working directory changes.
