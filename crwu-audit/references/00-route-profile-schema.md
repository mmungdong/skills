## 1. 输入：氚云「报告审核」记录必读字段（schema Srabfcm8figc1xuzxawc5u04x5）

| 信号 | 字段 | 用途 | 强制 |
| --- | --- | --- | --- |
| 报告名称（委托方+经济行为+标的+对象） | `F0000049` | 主线/对象主源；弱结构化兜底唯一依据 | 必读 |
| 报告形态（4 值） | `F0000056` | 体裁层（决定条款强制力） | 必读 |
| 业务大类（23 值） | `F0000065` | 经济行为主线 | 必读（空→名称兜底） |
| 评估目的（36 值） | `F0000064` | 主线细分 | 必读（空→名称兜底） |
| 范围 / 对象大类 | `F0000066` / `F0000119` | 对象专项挂载 | 必读 |
| 价值类型 | `F0000072` | 口径（市场/公允/可回收/清算/残余…） | 必读 |
| 法定/非法定 | `F0000051` | 条款强制力 | 必读 |
| 基准日 | `F0000067` | 时效核查 | 读 |
| 报告文号 | `F0000092` | 披露一致性 | 读 |
| 监管归属 | `F0000082` | 国资覆盖层 | 读 |
| 司法/证券/金融标志 | `F0000126` `F0000127` `F0000124` | 覆盖层判定（见 02） | 读 |
| 附件字段（文件名数组） | `F0000076` 等附件键 | **方法第一提示源** | 读文件名即可 |

- 记录字段变动（新增/改名标志、词表取值变化）由基线脚本监控：
  `画像基线/pull_全量画像.py`（工作区过程稿；正式基线入库待迁 crwu-knowledge 统计层）。

## 2. 弱结构化兜底
- 业务大类/目的为空（基线约 700 条）→ 必须读 `F0000049` 名称推理 canonical 角度；
- 名称含混推不出 → 输出"画像歧义，需人工确认"，**不猜测分发**。

## 3. route_profile 画像 schema（分发输入，JSON v0.1）

每个字段带 `source`（字段 / 名称推断 / 附件名 / 材料抽验）与 `confidence`（高/中/低）。

```jsonc
{
  "route_profile": {
    "report_form": "资产评估业务",
    "main_angle": { "canonical": "转让处置-资产", "f65": "资产转让、置换、拍卖",
                    "f64": "资产处置", "name_evidence": "拟处置…的市场价值评估" },
    "object": { "object_class": "设备类", "scope": "单项资产", "describe": "（F0000049 摘要）" },
    "value_type": "市场价值",
    "methods": [ { "method": "市场法", "source": "附件名/待抽验", "confirmed": false } ],
    "base_date": "2026-07-31", "doc_no": "…", "legal_or_not": "法定评估业务",
    "regulatory_overlays": ["国资-国家国资委"],
    "weak_structured": false,
    "material_gaps": [],
    "confidence": { "overall": "中", "note": "主线由字段直接命中；方法待抽验" }
  },
  "dispatch": { "L1": "crwu-audit-equipment", "L2": null,
                "route_path": ["字段画像", "L1命中", "L2未命中→降级L1"],
                "kb_ready": false }
}
```

## 4. 置信度与来源标注规则
- 字段直读 → 高；名称推理 → 中/低（须标 source=名称推断）；
- 方法未确认前不得在分发结论中使用"已采用某法"的强表述；
- 三条来源（字段/名称/附件名）冲突 → 交 02 冲突检测（ROUTE001–004）。
