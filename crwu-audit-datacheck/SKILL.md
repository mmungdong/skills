# crwu-audit-datacheck（表格/数据勾稽 · 能力型）

## ⚠️ 调用前置条件
本技能是跨方向**能力型**技能：默认由总路由 `crwu-audit` 编排后作为叠加模块调用
（材料含测算/明细/汇总表时自动挂接），**禁止 Agent 脱离编排直接调用并据其输出下审核判断**
（差异清单必须交回对象/方法规则技能判读，否则判断口径漂移）。
例外：用户明确只要「数据/表格勾核差异清单」且不做审核判断时，可独立执行本技能——输出仅限
差异清单，并注明“仅数据核对，未做审核判断，待规则技能判读”。

## 定位与触发
- 何时用：待审材料含 `.xlsx/.xls`（评估明细表、市场法计算表、成本法汇总表、租金倒算表等），
  或叶子技能要求先跑表格勾稽（rent/realestate 的明细表分区必做步骤）。
- 与知识库口径：对应 `M-数据校对`（`crwu-knowledge/audit-skill/03-模块-数据校对.md`）与
  `08-审核统计与台账规范.md` 的 `data_diff_count`；规则判断交回对象/方法技能。

## 前置与工具链（依赖说明）
- `.xlsx`：优先 `python3` + `openpyxl`（读缓存值 `data_only=True`；再开一档读公式串做公式审查）。
  未安装时可用 Python 标准库（zipfile+xml）读值（本会话已用此方式跑通）。
- `.xls`（老二进制）与**公式重算**：需 LibreOffice headless：
  `soffice --headless --convert-to xlsx --outdir <dir> <file.xls>`（含 `.xls→xlsx`、公式重算需 `--convert-to xlsx:Calc MS Excel 2007 XML` 后以 data_only 读取，或用 macro 强制重算）；
  环境中无 soffice → 如实声明"该表未能重算/未能解析"，计入未核表清单，禁止猜测。
- 安装（如允许）：`python3 -m pip install --user openpyxl`；LibreOffice 需按系统安装。

## 主流程
0. **H0 人工隐藏区强制跳过（铁律 · 最先执行）**
   - 业务依据：人工隐藏的 sheet / 行 / 列（含折叠分组）是**检查人已明确跳过、无需关注**的区域
     （说明性模板、资产负债表 0 值区、备用列、跨项目遗留工作区等）；审核口径必须与人工一致：
     **只审可见区，隐藏区一律跳过——不检查、不评论、不产生差异**。
   - 强制要求（不可放宽）：
     1) **识别先行（只读元数据，不得取隐藏区单元格值）**：列出隐藏 sheet 名单与隐藏行/列段位——
        `openpyxl`：`ws.sheet_state`、`ws.row_dimensions[r].hidden`、`ws.column_dimensions[c].hidden`；
        折叠分组 `outlineLevel>0` 且组头 `collapsed=True` 视同隐藏；标准库 zipfile+xml 读
        `<sheetState>`/`<row hidden="1">`/`<col hidden="1">` 同效。
     2) **禁读禁报**：隐藏 sheet / 隐藏行 / 隐藏列上的任何单元格值**不读取、不解析、不核对、不引用**，
        不进入 C1–C6 任何判断；对隐藏区**不产生差异、不产生意见、不写入证据值**——其公式错误
        （#REF!/#DIV/0! 等）、串扰词、占位残留等一律不报（员工检查同样跳过，agent 不得比人工更严）。
     3) **合计口径**：合计勾稽只看**可见区**；若合计公式引用范围覆盖隐藏行/列（SUM 跨到隐藏区），
        该合计按可见引用范围核、隐藏部分不逐格核，并在差异清单注明"该合计含隐藏区引用，仅核可见部分"
        （不因隐藏部分报漏/报错）。
     4) 输出忽略清单（仅元数据，无内容值）：`已跳过隐藏 sheet N 个（名单）、隐藏行 M 行、
        隐藏列 K 列（段位）`；如确有需要人工抽查隐藏区，另行导出《隐藏区内容快照》**给人工**，
        不进自动差异、不进意见单。
     5) 除非委托人/审核负责人明确书面要求，禁止 Agent 事后回头检查或披露隐藏区内容。
1. **清单盘点**：列出材料包全部表格文件，标注每张表角色（明细/计算/汇总/填表说明/模板残留）。
2. **解析**：按工具链读取**可见区**的值与公式；按 H0 记录隐藏元数据并生成忽略清单；记录每表
   sheet 名、可见行数、可见区含公式/错误单元格数量。
3. **六类检查（只在可见区执行）**（命中才记差异）：
   - C1 合计/勾稽：可见明细行求和 vs 表内合计 vs 汇总表合计 vs 报告结论金额/面积（单位一致）；
   - C2 跨表一致：同一口径（面积、租金单价、月/年租金、含税与否、物业费是否含入）在各表与报告间一致；
   - C3 公式错误：只扫**可见区**单元格（`#REF!`、`#DIV/0!`、`#N/A`、`#VALUE!` 等）；
     隐藏 sheet / 隐藏行 / 隐藏列中的错误单元格**不扫描、不报**（H0 铁律）；
   - C4 单位/小数：元 vs 万元、㎡ vs ㎡/月、单价×面积≈总价（±舍入）等；
   - C5 跨项目模板串扰：只扫**可见区** 项目名/坐落/房屋名称/权证号/页码 等是否残留**其他项目**内容
     （如同一机构同系列模板漏替换，如"红桂路2087"出现在"红宝路39号"表内）；
   - C6 口径与假设残留：只扫**可见区** 模板固定文字、占位（xxxx号文号、日期序列号未格式化、无关表数据 0 值大行）。
4. **输出差异清单**（不下价值判断）：每条 = 表名/sheet/位置(行或单元格) + 类型(C1..C6) +
   证据值（表内 vs 表外/报告值）+ 建议核验动作。供调用方（rent 等技能）按 CHK/RULE 出规则意见，
   例如：汇总数与报告结论不符 → 反证报告数字污染（RULE-01-02-561/576/254 语境）；
   修正系数表与说明不一致 → CHK-MKT-013；公式错误表参与汇总 → 高优重算。
5. **收尾**：明确列出"已核表 / 未核表（含原因）"与"已跳过隐藏区（仅元数据）"；差异条数进入台账 `data_diff_count`。

## 边界与纪律
- **H0 铁律**：隐藏区（sheet/行/列/折叠分组）内容任何 Agent/引擎**禁读禁报**——不得读取、核对、
  引用或输出其值，不得对其产生差异/意见（含公式错误、串扰、占位）；违反视为执行错误。
- 只核对数值/一致/错误，不评估"修正系数定得合不合理、折现率选得对不对"（那是方法技能职责）；
- 数值以表内公式缓存或重算值为准，禁止心算替代；无法核的表必须明示；
- 含真实客户数据的表只在本地产出，不外发、不入 git（沉淀前脱敏）。

## 校准实例参考（2026-09 试点，按 H0 口径复核）
- BG8169：可见区合计 1,499㎡/96,300 元·月 与报告红宝路表一致 → 反证报告正文（可见区）残留红岭店表
  （233,000）为污染；可见区"报告说明用表/页眉"残留红桂路2087；畸形户型备注"半折"与折扣率 0.03
  语义需澄清。隐藏模板区（如办公房产案例表等隐藏 sheet/行/列）内容按 H0 强制跳过，不报。
- BG4468：市场法案例筛选表基准日 2025-07-31 vs 报告 06-30（版本待核）；楼层修正指数取数
  "百度文库"非权威来源需核对披露。
