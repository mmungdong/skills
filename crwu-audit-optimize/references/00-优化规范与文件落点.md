## 1. 引用协议与运行时真身（2026-09-08 实时引用协议；2026-09-10 本地根模型废止）

- **知识库 = 钉钉知识库（crwu-dws 实时下载源）**。技能正文不保存、不缓存知识库正文：引用一律写
  RULE/CHK 编号 + 库内层级路径寻址键（如 `00-总纲/执行契约/01-调度器-SKILL总纲`、`06-规则库/…`），不写知识库名称、
  不写本地根路径字面、不写 nodeId；需要正文时经 crwu-dws 按清单实时下载后只读引用
  （出处 = 本次下载文件:行号 + exportedAt，下载时刻即最新）。
- **本仓不再有本地知识库根**：`CRWU_KB_ROOT` 与 `KB/<相对路径>` 引用均已废止。技能侧只保留
  寻址键；是否存在、是否改名一律以 crwu-dws 的**最新目录**为准（本地目录缓存只用于定位加速，
  不能提供正文）。校验 = `crwu-audit-skill-maintainer` 技能的 `scripts/kb_tool.py validate --skill-root …`（引用卫生 + "三不写" lint：
  禁知识库名称 / 禁本地正文路径字面 / 禁 nodeId 常量；见 §4）。
- 运行时布局（事实）：真身 = `~/.skills-manager/skills/`；`~/.dsh/skills/` 与 `~/.workbuddy/skills/` 为其软链视图
  （三者指向同一份文件）。**部署/同步由用户 skills 管理机制负责**：维护者/agent 只改源仓并提交，
  不直接写/ln/cp/rm 任何运行时目录（校验以管理机制结果为准）。
- **工具**：`crwu-audit-skill-maintainer` 技能的 `scripts/kb_tool.py`（**随该技能安装**；唯一子命令 `validate --skill-root`）。
  命令按 skills 安装根寻址：`python3 "$SKILLS_ROOT/crwu-audit-skill-maintainer/scripts/kb_tool.py" …`（源仓内的 `$SKILLS_ROOT` 即 `<源仓>/skills`）。
  装配清单不再由工具生成——下载清单 = 命中叶子的 `references/01-kb-assembly.md`（一级目录根或单文件路径）
  ＋ 执行契约路径并集，由 crwu-dws M2 实时下载。无工具时按装配表定位引用路径，正文一律经 crwu-dws
  实时下载后人工核对，**方案必须附手工证据**；下载不可得 → 显式报告。
- 本技能 references 随技能安装，内容自带寻址键表与落点地图，不回指 skills/README（该文件不装到 agent）。

## 2. 分层地图（改动类型 → 唯一落点）

> **执行分界（2026-09-10）**：本表是"改动落在哪个文件"的地图。**谁执行**按桶分——A/C/D（规则内容、词表取值、技能算法与流程）由本技能执行；**B/E（一级 Skill 的新增/改名/结构/一级根/registry/classification）一律交接 `crwu-audit-skill-maintainer`**，本技能只给根因与最低改动集，不自行改结构（见 SKILL.md §2、§2.1）。

## 2.1 知识库变更的同步义务（装配表 / 知识库登记 两件套）

> **铁律：技能里不得留下指向已不存在路径的寻址键。** 下载清单直接由叶子装配表产生，
> 指针一旦漂移，本次审核就会漏装或多装文件；禁止出现"文件已动、指针没跟"的中间态。
> 本流程收尾以 `validate` error=0 ＋ 受影响装配导出两跑一致 为准。

| KB 变更类型 | 必做同步 | 说明 |
| --- | --- | --- |
| 条目正文/判定要点/dims/modules/标题（同文件内编辑） | ① validate ② 受影响装配导出两跑 | 装配表指针不受影响，不用动；正文本身按知识库维护流程改 |
| 同文件新增条目 | ① 批次 README/进度总表对应行（条目计数/段位变化时） | 新增条目须先登记词表取值（若用新标签）；`### <id>` 锚点唯一 |
| 新增/改名/移动/删除 KB 文件或目录 | ① 受影响叶子的 `references/01-kb-assembly.md`（路径键行）② KB `00-总纲/README`（总纲登记行）③ 相关文档内引用文本 ④ validate | 改名前先 grep 全库引用（装配表/SKILL/治理文档），一个不漏；一级目录根改名交 `crwu-audit-skill-maintainer` 重映射 |
| 装配范围/模块标签体系变化（某技能该装哪些清单与规则段） | ① 对应叶子 `references/01-kb-assembly.md` ② 词表登记（若模块/取值变化）③ validate | 影响"命中/排除"语义，须重跑受影响画像两遍验证 |
| KB 引用路径/文件名出现在技能正文中（SKILL.md） | ① 技能正文同步 ② 装配表同步 ③ validate --skill-root | 个人绝对路径、「KB/…」式前缀省略（技能引用一律=库内层级路径寻址键）、已废止的 `KB/<rel>` 与 `CRWU_KB_ROOT`、知识库名称 / 本地正文路径字面 / nodeId 常量一律禁止 |
| 校准/回测结论更新（案例覆盖、缺口 G） | ① `校准案例记录.md`/`回测报告-真实案例覆盖.md` 回填 ② 受影响清单/规则条目若改 → 同步装配表路径键 | 回测与规则互为证据链，不同步=下次优化失去基线 |

**知识库侧缺口（2026-09-10T18:12 经 crwu-dws 实时目录核对，库侧待处理，不代改）**

- 00-总纲/目录地图 **已从库内移除**：同位置现为 `00-总纲/历史数据资产 x 业务数据统计`（内容为氚云「业务行为 × 资产类型」项目统计表，**不是目录映射**，不能替代）。

## 3. 红线（不许绕过）

1. **未出方案、未经用户确认，不动任何文件**（含 KB 内容）；
2. 不产审核判断、不出审核意见（那是 crwu-audit 流程）；
3. 不判定、不依赖"发布/待发布"状态（口径 2026-09-08：知识库文档即权威、下载即审——不存在发布状态
   判定与登记动作；内容侧历史"待发布"标注仅信息残留，AI 不读取判定，清理归知识库维护）；
4. 不把规则/清单正文复制进技能（技能=流程+寻址键+算法，正文=钉钉知识库，即 crwu-dws 实时下载源）；
5. 编号唯一性以定义锚点为准（正文区间引用不算重复）；
6. 个人绝对路径、「KB/…」式前缀省略、已废止的 `KB/<rel>` 本地根相对引用与 `CRWU_KB_ROOT` 常量、
   旧树目录名（01-规则库/02-审核清单库/执业准则-*/06-素材库-L2 等）一律禁止出现；
7. SKILL.md ≤300 行；改 crwu-audit 族技能前先读 `crwu-audit/references/99-维护说明.md`；
8. 每次改动只落源仓并提交；运行时部署由用户 skills 管理机制负责（不直接写/ln/cp/rm `~/.skills-manager`、`~/.dsh`、`~/.workbuddy` 等运行时目录）；登记三处（design/README/CHANGELOG）。

## 4. 验收基线（每次优化完成后必须全过）

```bash
# 1) 双份校验：error 必须为 0（warn 相对基线不得增加）
python3 "$SKILLS_ROOT/crwu-audit-skill-maintainer/scripts/kb_tool.py" validate --skill-root <源仓>/skills --skill-root <运行时真身>/skills
#    validate = 引用卫生（旧树残留 / KB/… 省略号 / 已废止的 KB/<rel> 与 CRWU_KB_ROOT / 字面路径是否存在）
#             + "三不写" lint（禁知识库名称 / 禁本地正文路径字面 / 禁 nodeId 常量）
# 2) 映射一致性：registry ↔ classification ↔ 真实技能目录 ↔ 最新知识库目录
python3 "$SKILLS_ROOT/crwu-audit-skill-maintainer/scripts/check_audit_skill_mappings.py" \
  --repo-root . --catalog <最新 DWS 目录快照 或 node-index 或 目录树.md>
# 3) 装配可复现：受影响示例（含本单画像）两跑导出 diff 为空
#    按叶子 references/01-kb-assembly.md 的路径键经 crwu-dws 导出两次，比对文件名集合与 exportedAt
# 4) 案例回归：BG8169 / 300673 输出不劣化（见知识库回测报告 §5）
```

通过判据：error=0；装配两跑一致；受影响案例输出无劣化；源仓 ↔ 运行时真身 diff 空（三处视图一致）；登记完成。任何一条不过 → 回到方案修订。

## 5. 顺序纪律（确认后的执行顺序）

落点文件 → 引用它的上层文件 → 登记（词表/路由表/design/README/CHANGELOG/批次 README）→
`validate` → 装配导出两跑 → 案例回归 → 汇报（文件级清单 + 校验结果 + 剩余风险）。
