# references/99 · 维护说明（改本族技能前必读）

| 版本 | v0.1 | 状态 | 守门文档 | 适用 | 任何对本族技能（SKILL.md / references/ / 叶子技能）的修改 |
| --- | --- | --- | --- | --- |

> 目的：本族入口与分发逻辑会持续被 Agent/人维护；本文把"哪类改动只能动哪个文件、
> 怎么改、改完同步什么"固化成流程，**防止改动打散整体结构**。

## 1. 分层地图（哪类改动 → 哪个文件）
| 改动类型 | 唯一落点 | 联动 |
| --- | --- | --- |
| 输入字段 / 画像 schema / 置信标注 | `references/00` | SKILL §1/§2、KB 01 |
| 新增/改名/删除审核角度、判定、体量 | `references/01` | 02、SKILL 示例路由、基线脚本、台账口径 08 |
| 覆盖层判定、忽略名单、冲突检测 | `references/02` | 00 输入表、SKILL §2 步骤5/7 |
| 分发流程步骤、路由注册表状态 | `SKILL.md` | references、design §4 |
| 规则正文/检查点 | **禁止进本族**（由部署环境注入；本族不维护、不引用其仓库路径） |
| 族架构/变更记录 | `docs/design-crwu-audit-skills.md`、`docs/CHANGELOG.md` | skills/README |

每个文件顶部保留"版本/日期/状态/维护"表；同文件多人多轮维护时更新该表。

## 2. 标准改动流程（照抄）
1. 定位改动属于 §1 哪一行（层）；
2. 改对应 references/SKILL.md（先改"落点"文件，再改引用它的上层）；
3. 同步两处拷贝：repo `skills/crwu-audit/` 与 `~/.dsh/skills/crwu-audit/`（安装目录是拷贝非软链）；
4. 登记：`docs/design-crwu-audit-skills.md` §4/§5 + `skills/README.md` + `docs/CHANGELOG.md`（向下追加，格式见头部）；
5. 回归：旧试点 BG8169 / 300673 输出不劣化；词表/字段口径变化时重跑
   `pull_全量画像.py` 复核；
6. 联动：涉及统计口径/输出契约 → 与部署环境的外部契约保持一致（本族只维护分发材料）。

## 3. 红线（不许绕过）
- `SKILL.md` ≤300 行（极限 500），**不内嵌大段 schema/词表/覆盖层表**——只放流程+注册表+指针；
- 弱结构化名称兜底与"画像歧义→如实返回"不允许被猜答案替代；
- 风险等级 ABC / 级次 / 状态不参与路由与判定（口径自 2026-09-07 定稿）；
- 不复制外部规则正文进本族；三段式引用与试点门禁（`[依据待发布]`）不透传失效；
- 新增任何 crwu-audit-* 能力：路由注册表（SKILL §3）+ design §4 + skills/README 三处登记缺一不可。

## 4. 最小改动示例 walkthrough
目标：给 references/01 加一个"商誉-单独减值"角度。
1. 层定位 → 01；
2. 在 01 表加一行（canonical/判定/体量/技能）；若该角度改变覆盖层装载 → 同改 02；
3. SKILL §4 示例路由视需要加一行；注册表若对应新技能 → 加行 + 三处登记；
4. 同步 `~/.dsh/skills` 拷贝；design/README/CHANGELOG 各记一条；
5. 用 1 条该角度记录跑分发验证 + BG8169 回归；
6. 台账口径（08）若按角度统计 → 注明新角度并入或单列。

## 5. 散架自查清单（每次改完自问）
- 入口仍只做分发、不产判断？
- references 与 SKILL 指针一致、无大段正文复制？
- 两处拷贝同版本（`diff -r` 为空）？
- design/README/CHANGELOG 已登记？CHANGELOG 只向下追加？
- 词表/覆盖层/弱结构化三类契约是否有既改文件外的游离副本？
